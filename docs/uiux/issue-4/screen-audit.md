# TermCraft Fluent 1 screen audit

Source review of the native egui application on issue-4-fluent-ux. Locations below identify the starting source, before the implementation batches. The defects are visible in the rendering or interaction code. Runtime inspection at minimum size, in a detached window, and at larger UI scale remains part of implementation verification.

## Shared controls and shell

| Surface | Source | Observations |
| --- | --- | --- |
| Theme and typography | src/ui.rs:66, 725–805, 2036–2045; src/ui/appearance.rs | Light and dark styles already preserve the emerald identity and honor the OS theme, including Linux portal fallback. All standard widgets inherit 14-point labels and 30-point interaction height. Custom controls bypass several state styles. Semantic error, warning, and success colors are inconsistent across modules. Default scrollbar and animation settings are inherited from egui. White on the light accent is approximately 5.4:1. The legacy dark-red form error has approximately 2.6:1 against dark panel fill. |
| Title, menu, commands and status | src/ui.rs:1305–1571 | Standard menus have inherited state behavior. The title, menu and wide command rows consume three separate vertical bands. Command tiles have 56×54 hit regions and accessible labels, but focused and hovered paint are identical, pressed and selected states have no dedicated paint, and all tiles occupy a single row. The checked state of Sessions and MultiExec is available through behavior or hover copy only. The narrow status row truncates messages, uses a perpetual green dot, and has no way to read the full truncated message in place. |
| Navigation and session sidebar | src/ui.rs:1572–1831; src/ui/shared_sessions.rs:1140–1265; src/ui/session_groups.rs | Rail rows have selected widget metadata and an active indicator. Hover borrows the selected fill, keyboard focus has no distinct visual, and the fixed rail has no scrolling. Sessions and Local files use the same glyph. The session sidebar resizes and persists changes only after real handle movement. Its quick connect has Enter submission, but the host label is a placeholder. Saved rows launch only on mouse double click or through a context-menu action. Session search filters children after generating the folder list, so empty matching folders remain. The viewport reserves 80 points for the footer and forces at least 150 points for the list after other sidebar chrome has consumed space. Tiny plus and glyph-only actions rely on tooltips for names. Shared source rows have independent grouping and scrolling inside the saved tree. |
| Workspace tabs and Home | src/ui.rs:1903–2034, 2219–2384; src/ui/activity.rs | Tabs support horizontal scrolling, stable IDs, distinct chosen state, focus outline, full titles on hover, and separate close hits. Keep the close-hit regression coverage, middle click, context menu, rename, detachment and activation. Selected tabs have a focus ring; nested close only paints hover, with no focus or pressed indicator. Tab text is clipped without ellipsis; running state is a small dot with no explicit status in the accessible label. Home is already vertically scrollable and has bounded content width. Preserve the penguin mark and vault notice. |
| Splits and detached windows | src/ui/layout.rs:75–255; src/ui/windows.rs:174–275; src/ui/broadcast.rs; src/ui/shortcuts.rs:473; src/ui/session_confirmations.rs:540 | Split panes already fall back to one active pane when the requested tree cannot fit. Chosen pane has an accent border. Split handles are pointer drag regions with resize cursors; keyboard users have layout commands but no direct equivalent for proportion adjustment. Pane close is a small glyph. Detached viewport shares UI styles, with 360×260 minimum and therefore different overflow constraints than the 920×620 main window. Preserve focus ownership, dirty-close and broadcast confirmation rules, clipboard paste previews and shortcut suppression. |

Top game commands and play status are straight rows inside an outer two-axis scroll area. Boards may also scroll in both directions. The noVNC web-client shell is an additional app-owned frontend reachable from the managed VNC service. TermCraft supplies assets/vnc-browser/index.html, viewer.css and viewer.js through src/services/vnc/browser_assets.rs. The form already wraps, labels its controls, defaults to View only, prominently states transport limitations, and exposes a live status region. It uses a fixed dark theme and mostly browser-default inputs and buttons. Preserve password length and role, disabled controls, connection status, and the transport notice if bringing this shell into the Fluent pass. Bundled third-party noVNC rendering, browser tabs, clipboard permission surfaces, native file pickers, system title bars and remote host content remain platform or provider-owned.

## Suggested ownership batches

1. Foundation and shell. Own both theme variants, semantic state colors, shared buttons and row states, motion and scroll behavior, title/menu/toolbars, navigation rail, sidebar tree, workspace tabs, split chrome and Home. Verify focus and pointer hits separately.
2. Forms and local pages. Own session/protocol forms, local files, tunnels, macros, Settings, Tools, Servers, packages, plugin UI and shared sizing patterns for safety dialogs. Check narrow viewport behavior and resizing while entered values remain intact.
3. Remote tools. Own browser, SSH remote files, FTP, both editors, RDP/VNC/XDMCP chrome, detached panes and specialist status. Keep protocol, input and trust behavior unchanged. Verify no critical action can scroll out of reach without a means of recovery.
4. Games and visual QA. Own shared game chrome, catalog, option panels, indicators, board contrast and responsive scrolling. Preserve existing seed/game behavior and screensaver privacy. Exercise light/dark and larger text with actual application output across the four batches.
