# Fluent 1 dialog audit

This document records the starting review. The [integrated verification record](validation.md) gives the final disposition and evidence for these surfaces.

Source review for issue 4. References identify the current implementation, including dialogs that render outside the root dialog dispatcher. The native session screenshot at `target/readme-capture/session-dark.png` is the existing reproducer. This audit did not launch the app or run Cargo.

## Shared implementation priorities

1. Give short blocking decisions a centered ContentDialog surface, a dimmed backdrop, a clear title, wrapping body text and an aligned action row. Focus the safe choice for destructive and trust decisions, and map Escape to safe cancellation where allowed. Avoid implicit approval from Return, focus restoration or backdrop clicks. Preserve existing explicit-only behavior when a controller requires it.
2. Use one viewport-budgeted body scroll region with its header, validation message and action footer visible. Size in logical points from the owning viewport and allow narrower field layouts. Hard minimums from 480 to 640 points and static heights from 260 to 590 points currently combine into surfaces that can exceed the usable window. Long paths, identifiers and fingerprints must remain available in full through wrapping or a full-value detail control.
3. Use square or subtly squared Fluent 1 surfaces with one-pixel theme borders, subdued neutral light/dark backgrounds, emerald for a single safe primary action or selection, and consistent error/warning colors. Make keyboard focus visible and restore it to the opener where possible. Keep resizable editors, task managers and reference reports modeless, with normal title-bar close and consistently placed contextual commands.
4. Eguis modal backdrop and focus behavior do not automatically centralize application command routing. `ui.rs:2164` renders the workspace, collects input and handles root shortcuts before several dialogs. `shortcuts.rs:254` uses a state-based gate whose current list omits local and remote file actions, tunnel and macro windows, and remote recovery review. It also assigns the same focus context to some modeless tools and blocking prompts. Gate underlying terminal, desktop and game dispatch using the actual pending blocking state and owning viewport. For modeless windows, let focused fields claim editing keys while input in an independently focused terminal still works. Route at most one actionable blocking decision per viewport so independent prompts cannot accept the same key. Preserve existing shared sign-in/vault and game/session close handoffs.

## Native surfaces

OS file pickers come from `rfd::FileDialog` and should use the platform's native styling. Call sites cover session paths/keys and workspace imports/exports (`pages.rs`), session import (`session_import.rs`), shortcuts (`session_groups.rs`), local and remote transfers (`remote_files.rs`, `ftp.rs`), game save/load (`games/save.rs`), protocol config/certificate/drive paths (`ssh_options.rs`, `rdp_settings.rs`, `vnc_settings.rs`, `ftp_settings.rs`), shared sources (`shared_sessions.rs`), keys (`ssh_keys.rs`), packages/plugins (`packages.rs`, `legacy_packages.rs`, `plugins.rs`), tools (`tools.rs`) and server configuration (`servers.rs`, `managed_servers.rs`, `managed_ssh_iperf.rs`, `xserver.rs`). Keep current row ownership, asynchronous picker cancellation and platform filters. Native detached terminal viewports (`windows.rs:206`) and game lifecycle/test viewports are separate window surfaces. The “Owned overlay” constructor in `desktop.rs:1622` is test-only.

## Visual and interaction checks for implementation

- Capture New and Edit session with dark and light appearance at desktop size and a short viewport, including expanded SSH, RDP, XDMCP and Browser options. Verify Cancel and every commit action stay visible and each body field can be reached. Check narrow reflow with long host, key and folder values.
- Verify mouse, Tab and Escape on a short blocking confirmation. Send no input to a previously focused terminal while confirmation owns it. Check Return in an empty text draft and when a potentially destructive action does not have focus.
- Exercise nested Session → Manage keys and Shared sign-in → Credential vault, detached rename/close, active-session close reached from the game, and FTP/SSH dirty document close. Focus should restore to the correct owner and existing identity and cancellation behavior should hold.
- Keep report/recovery comparison and document windows interactive while another modeless window is visible. Check long lists in shortcuts, key agents, shared sources, import warnings and remote documents with compact viewport dimensions.
