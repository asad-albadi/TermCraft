# P06 independent premerge review

Progress at review: 55.0% (33/60 implementation checkpoints). Review applies to `target/agent-work/p06`, before integration. The inspected implementation provides explicit full-account NativeExecution permission, disabled-by-default installation, release-specific grants, process isolation, bounded IPC and explicit limitations on original `.mxt3` compatibility. No native Windows or macOS execution is claimed.

## Important findings

1. **Freeze the verified executable bytes before Linux execution.** `src/plugins/registry.rs:282–298` hashes the installed file then passes that same writable filesystem inode to `src/plugins/host/unix.rs:23`, which executes `/proc/self/fd/<fd>`. Holding a read-only descriptor prevents pathname substitution, but does not prevent another writer changing that inode after the hash and before exec. An update by a file synchronizer, editor or concurrent process can therefore execute bytes outside the granted release digest. The existing altered-binary test covers modification before hashing only. Use a private verified executable snapshot or sealed executable image, and keep it alive through invocation. Add a deterministic mutation-after-verification regression. A standalone Linux experiment during this review opened and hashed an ELF, rewrote that inode with another ELF, and executed the held `/proc/self/fd` path: output was `replacement`, proving that the descriptor does not freeze the verified bytes. This reproducer used temporary reviewer-owned binaries only; no production files were changed.

2. **Avoid making plugin pipes inheritable in the main process.** `src/plugins/host/windows.rs:57–62` sets HANDLE_FLAG_INHERIT on the invocation's stdin-read, stdout-write and stderr handles in the application process before calling CreateProcessW. Its HANDLE_LIST constrains this plugin child, but cannot constrain an unrelated concurrent child creation elsewhere in the application. A concurrent ordinary piped child spawn can inherit these plugin pipe ends, read the invocation request or keep stdout alive after plugin termination. These main-process handles remain inheritable for the whole launch preparation window. Use the isolated bootstrap pattern already implemented for the browser, or another process-wide solution that actually covers every child creation; clearing flags after CreateProcess does not remove the overlapping race. Add the Windows overlap/EOF ownership regression, and retain the explicit no-native-execution limitation here until it can run on Windows.

3. **Preserve concurrent user replacements during retirement.** `src/plugins/registry.rs:405–408` opens and hashes a release filename, then unlinks that filename after the checked descriptor has been consumed. Replacing `bin/<executable>` or `notices/LICENSE` between the hash and unlink causes cleanup to delete the replacement, contrary to the promised retention of modified/user files. The lease protects cooperating plugin invocations, not user filesystem edits. Adopt the identity-aware quarantine/retention approach added to the current P05 implementation; test a controlled replacement between verification and retirement. Do not import the older P06 package-helper patch over newer P05 safeguards.

4. **Make retirement hashing cancellable without holding the registry lock.** `src/plugins/registry.rs:350–367` holds `registry.lock` while hashing every retired release, and `cleanup` calls `digest_entry`, whose cancellation flag is permanently false. `install`, `remove`, and `run_inner` call this collector before their cancellation checks. With up to 128 retired records and two files bounded at 8 MiB each, a request can perform roughly 2 GiB of reads/hash work while cancellation is ignored and all enable/disable/registry operations fail Busy. This is especially observable on slow portable storage and contradicts the cancellable Remove/Install UI. Snapshot retirement records under the registry lock, release it during cancellation-aware cleanup under a separate cleanup lock, and commit only completed identities afterward. Add a cancellation/concurrent registry-operation regression. The latest private P05 already has this structure, but P06 maintains a separate older collector.

## Verification scope

This was a source review of the plugin host, manifest/install/registry, UI, tests, shared handoff patch, and the latest private P05 cleanup structure. The short reviewer-owned native ELF experiment confirmed finding 1. Existing implementation evidence reports seven Linux plugin cases and component-only Windows checking; this review did not rerun that suite or turn component checks into native qualification. Findings 2–4 follow directly from the inspected ownership and call sequence; deterministic implementation regressions should accompany the fixes. No production source or private feature source was edited by the reviewer.

Disposition: resolve the four Important findings before merge; then request a scoped fix review.
