# P01 review fixes

The Linux release check requires the RDP child to execute the specifically named memory file, match the package digest, and carry all four required kernel seals. A direct launch from the installed file now fails the check even when its bytes match. The earlier direct-path archive startup evidence was collected before the sealed launcher. [Direct-path regression](review-probe-red.log) · [Strict check](review-probe-green.log)

Mosh launch resolution, package byte verification, private executable preparation, and child startup run in a worker. At most four starts can be pending. Other terminals keep receiving input and rendering while a Mosh launch is delayed. Closing its tab or selecting Cancel startup signals the worker without joining it on the UI thread. The worker destroys an unclaimed child and its private resources. One delayed test exercised a Mosh tab, continued rendering and verified terminal input in another tab, then closed the pending tab and observed the owned child and private files disappear. A second delayed test cancelled before spawn and confirmed that the child never wrote its startup marker and the private directory disappeared. [Mosh startup and runtime verification](review-fixes-green.log)

The Tools panel and Connect use the same packaged Mosh verification. Both artifacts must pass their declared byte and architecture or interpreter checks. The selected absolute Perl and OpenSSH programs must be available. Existing profiles still use the installed provider, and the packaged mode never switches to that provider on error. The real staged-package test reproduced the missing-client status error, then rejected missing or changed files and completed strict SSH authentication and a genuine Mosh UDP terminal frame with empty client PATH. [Missing-client regression](review-mosh-completeness-red.log) · [Staged fixture and related tests](review-fixes-green.log)

Windows keeps the verified non-reparse helper open with read sharing through process creation, denying conflicting write and delete access. macOS executes the verified bytes from a private read-and-execute-only snapshot. The portable snapshot fixture replaced the original after verification and ran the original bytes from the snapshot. The Windows lock fixture and macOS snapshot source passed isolated platform-target compilation. Native Windows and macOS launcher execution remains unverified. [Native source checks](review-rdp-native-source.log) · [Snapshot and Linux verification](review-fixes-green.log)
