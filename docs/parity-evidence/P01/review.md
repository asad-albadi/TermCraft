## P01 independent review

This record captures four Important findings from source inspection before remediation. Tests were not rerun for this review. Line references identify the reviewed snapshot.

1. **The Linux startup probe can accept an unsealed helper.** `scripts/package-check-startup.py:78–86` accepts an executable at the installed helper path when its digest matches. A release that launches the original file can therefore pass the probe. The regression should require a matching digest and all required seals on the named memory file. An ordinary executable with the same digest should fail.
2. **Packaged Mosh preparation blocks the UI thread.** `src/ui.rs:1050–1054` resolves and spawns the session synchronously. `src/connection.rs:132–133` verifies the wrapper and client, and `src/process_unix.rs:74` prepares private copies by reading and hashing both again. Slow storage can stall repaint and cancellation. With a delayed fixture provider, the UI should process events during preparation, and cancelling before preparation finishes should prevent launch.
3. **Native RDP launch can reopen a different image.** On Windows and macOS, `src/desktop/mod.rs:655` launches the verified pathname after the verification read has finished. A replacement in that interval can change which bytes execute. A native regression should use two distinguishable harmless helpers and arrange replacement after verification. Only the verified image may launch, or launch must fail.
4. **Tools can report packaged Mosh available with a missing or corrupt client.** `src/ui/pages.rs:34` displays the wrapper provider. Its checks in `src/runtime/mod.rs:185–195` cover the wrapper, Perl and SSH, while Connect also requires the pinned native client. Stage the genuine pair and verify availability, then remove or alter only the client. Tools and Connect should both report the workflow unavailable. The expected status covers the wrapper, client, Perl and SSH.
