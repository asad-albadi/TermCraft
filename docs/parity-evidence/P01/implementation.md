# P01 protocol runtime catalog

Status: implementation and hardware-independent Linux tests are present. The clean-install and native-platform requirements remain open.

`RuntimeCatalog` resolves the embedded protocol engines independently of PATH. It distinguishes built-in code, pinned packaged executables, explicitly selected installed programs, and unavailable providers. Installed programs retain absolute paths and the catalog reports their versions as system-managed. The Tools page checks provider metadata in a background worker.

| Workflow | Provider and runtime requirements |
|---|---|
| SSH, SFTP, SCP | Embedded Rust engines. SCP compatibility additionally needs a POSIX remote host with Python 3 and atomic rename support. OpenSSH compatibility and SSH X11 forwarding can explicitly select the installed OpenSSH tools. |
| RDP | Package-adjacent IronRDP helper built from the workspace lockfile. The release worker verifies the package manifest, executable permissions, file type, SHA-256 and native header before starting the engine. Linux executes a sealed copy of the verified bytes. The package manifest is unsigned. The standalone release build writes a local unsigned manifest for its two binaries. Existing test and development helpers are available in debug builds. Installed FreeRDP and Windows Remote Desktop remain explicit alternatives. |
| VNC, FTP/FTPS, Telnet, Rlogin, Rsh, Serial | Embedded clients. Serial depends on native device access. Rlogin and Rsh require a permitted reserved source port for direct sessions. FTP/FTPS legacy and external VNC selections require installed clients. TLS uses the OS trust store. |
| Mosh | The Linux x86-64 Arch variant ships the pinned upstream wrapper and native client along with source, archive build inventory, license, recipe and the shebang patch. It uses installed system OpenSSH and Perl by absolute path and requires Arch library and terminfo dependencies. The remote host needs Mosh, SSH and a reachable Mosh UDP port. Existing profiles use explicit Installed Mosh. New Mosh profiles default to Packaged Mosh in the session form. The terminal executes private copies of the verified wrapper and client, which are removed when the process closes. |
| Browser | The integrated Linux browser resolves the absolute installed Chromium binary through the catalog, checks its native executable header, and uses a managed private pipe. Chromium is a System provider. The external browser choice uses the OS application opener. |
| X11 and XDMCP | The qualified Xwayland archive follows the separate pinned X01 verifier and Wayland launch contract. It requires a Wayland compositor and declared display libraries. XDMCP remains an explicit installed Xephyr or VcXsrv provider. |
| Local shell and file integration | OS shell or user-selected executable, environment, file opener, optional Wayland clipboard helper, and native shortcut integration. |
| Keys and diagnostics | Embedded key management, TCP diagnostics, port scan, local IP information, file comparison and image tools. Optional Ping, SSH service, server key generation and Iperf use installed clients. |
| Capture | Embedded packet reader and exporter. Live capture requires native, system-managed libpcap and existing privileges on Linux or macOS. |
| Native GUI | Host OpenGL or EGL, native display client libraries, serial/console APIs and OS certificate store as declared in package requirements. |

The application’s normal Mosh launch authenticated through an isolated loopback OpenSSH server with strict host-key checking, then displayed a distinctive terminal line delivered by the genuine Mosh server over UDP. The local PATH remained empty for all client-side processes.

The [local release declaration fixture](local-release-manifest.log) verified hashes for both actual prebuilt binaries, idempotent recreation, and preservation of a manifest owned by a different package.

This records package placement, corresponding source and native-library closure on the test machine.
