# B01 premerge review

**Changes requested.** Source paths below refer to the private B01 candidate. The findings are from static inspection. No host services were started.

- **Important — TFTP can answer an ERROR with another ERROR indefinitely.** At `src/services/tftp.rs:39–43`, the listener sends an error on every parse failure. At lines 94–97 the parser classifies an incoming ERROR as a failure. Two endpoints with this behavior can continue exchanging errors after the original request has ended. The worker retry count does not cover listener responses. Discard incoming ERROR datagrams before sending any response, including on the unknown-transfer-ID path. Verify with a single ERROR sent to each receive path and assert silence.
- **Important — Telnet can truncate terminal output when the shell exits.** At `src/services/telnet.rs:137–152` the bridge reads at most eight queued chunks before polling the child. It immediately closes on exit while the independent PTY reader can still have queued or unread output. A shell that prints a large final batch and exits can lose its final bytes even on a healthy connection. Drain the reader through EOF under the session deadline and cancellation checks. Verify a finite shell printing a known payload followed by a final marker, then exiting immediately. Check the complete payload.
- **Important — FTP cannot process a client abort during an active transfer.** At `src/services/ftp.rs`, the ABOR command is dispatched only in the outer control loop, while `transfer` synchronously owns that thread through data accept and I/O. If the client requests ABOR while holding an idle upload socket open, the server waits for the data timeout before reading the control request. The existing cancellation fixture at `tests/services.rs:242` stops the entire service instead. Poll for transfer cancellation alongside data I/O, clean up the staging file, and test that the same control session remains usable promptly after abort.
