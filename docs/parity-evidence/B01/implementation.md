# B01 managed FTP, TFTP and Telnet servers

The Servers page starts workspace-owned listeners with loopback defaults. Network exposure requires an explicit setting. Each service reports its bound address, startup failures and bounded status messages. Startup and connection work runs in dedicated workers. Stop closes owned listeners and joins their workers. The card can start a new instance after stop. Service credentials stay in memory and are excluded from workspace JSON.

- **FTP** supports password sign-in and optional read-only anonymous access. Authenticated writable shares support directory creation, upload, rename and removal. The embedded FTP client exercised listings, ASCII file round trips and mutations over active and passive data channels. Socket fixtures covered binary transfers. Data endpoints are constrained to the control peer. Portable share paths are validated before opening children of the selected directory without following symlinks. Uploads use bounded staging files and publish only when complete and the destination is free. ABOR interrupts data acceptance and transfer I/O, discards staged uploads and leaves the control session usable.
- **TFTP** implements UDP octet-mode RRQ and WRQ. The worker owns its transfer socket and enforces its peer transfer ID, ACK and DATA block numbers, retransmission and final ACK replay. ERROR packets do not elicit a response from either receive path. Write access is opt-in. Incomplete transfers discard their staging files.
- **Telnet** verifies its application credentials before allocating a PTY for the selected executable. Telnet negotiation includes window sizing. Sessions run with the workspace account's existing privileges. A shell that exits normally can finish delivering its PTY output before the connection closes. Closing an authenticated connection or stopping the service ends its owned PTY session.

Loopback port defaults are 2121 for FTP, 6969 for TFTP and 2323 for Telnet. The default TFTP lifetime is 360 seconds. FTP and Telnet are clear-text protocols. Directory listings and uploads have explicit size bounds. TFTP option negotiation falls back to the base 512-byte block size; transfers without block rollover support are limited to 65,535 blocks.

The tests cover bind conflicts, ownership, time limits, peer restrictions, symlink and traversal rejection, authenticated file operations, read-only permissions, concurrent upload conflicts, timeout cleanup and shell authentication. [Protocol tests](protocol-tests.log)
