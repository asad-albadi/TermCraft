# E03 managed VNC server candidate

2026-11-24. Private implementation at `target/agent-work/e03-vnc`, package version `0.1.0-e03-vnc-private`. Production sources are unchanged by this agent. Root review, merge and a fresh integrated gate are required. **E03 is not closed by this candidate.**

## Implemented behavior

`VncServiceConfig`, `VncSource`, `ServiceSupervisor::{begin_vnc,start_vnc}` and an actual Servers-page card own a separate RFB listener. Startup opens the explicitly selected source, verifies a real first framebuffer, then binds the requested endpoint. Start is asynchronous in the UI. Stop cancels workers and releases only the owned listener; the selected desktop is never terminated. Status and failures use the existing bounded service log. Optional lifetime uses the supervisor's 1-second to 24-hour limit; zero in the UI means until stopped.

Loopback is the default. Non-loopback listening needs a separate opt-in. Every listener requires a 1–8-byte printable ASCII password and explicit consent to classic unencrypted transport. Passwords are not silently truncated, do not implement Debug/ordinary serialization, and are cleared from the UI after Start, including parse errors. The existing password widget clears undo snapshots; a new regression checks it for the VNC field.

The server implements the RFB 3.3, 3.7 and 3.8 handshake, security type 2, fresh random challenge, constant-time response comparison, ServerInit, true-color 8/16/32-bit SetPixelFormat, bounded SetEncodings, Raw framebuffer updates, KeyEvent, PointerEvent and bounded ClientCutText parsing. ClientCutText is discarded and zeroized because clipboard sharing is not implemented. No TLS, VeNCrypt, HTTP/browser viewer, Tight compression, file transfer, extension clipboard or unattended secure-desktop access is advertised. Exclusive-client requests cannot evict an unrelated client.

The Linux provider uses pinned `x11rb = 0.13.2` with XTEST. It opens only an explicitly named **local** X11 display, never infers DISPLAY, and supports an optional explicitly selected authority file. Standard Xauthority lookup is read-only when a file is not supplied. Authority reads are bounded and opened without blocking on FIFOs. The X socket connects nonblocking and provider I/O has a two-second deadline per operation. The provider gets current pixels from the selected root window and its TrueColor visual; it does not serve a static/synthetic framebuffer. It rejects unsupported pixel formats, display resize and coordinate/framebuffer overflow. The qualified native fixture uses a rootful Xwayland desktop; a rootless compositor's Xwayland root is not claimed as a desktop-capture backend.

Remote control is disabled by default. Explicit opt-in enables XTEST key and pointer events on that selected display. The server allows one controlling client at a time and releases held remote input on disconnect/stop, including queue overflow. Multiple clients are supported by view-only listeners. Capture failure cancels the service rather than continuing to advertise a frozen desktop.

Bounds: 8,388,608 pixels per framebuffer; one latest shared framebuffer plus bounded snapshots held by at most eight client workers; 64 queued input events; 64 held keys; at most ten capture/update attempts per second; 256 advertised encodings; 64 KiB incoming clipboard text; five-second handshake-stage/message-body/frame-write deadlines; 300-second idle client timeout; cancellation checks during network reads/writes and between queued input events. Frame writes use one bounded row buffer. Source work and network work run off the UI thread.

The Windows provider is an **implemented, component-checked candidate**, not native-qualified support. It explicitly selects the current desktop's primary display, checks that the active input desktop still matches the calling thread's desktop, captures GDI pixels with GetDC/BitBlt/GetDIBits, and releases GDI resources on their creating thread. Optional SendInput maps keys and primary-display pointer coordinates, checks success and tracks releases. It does not switch desktops or attempt to bypass secure desktop/UIPI. Native Windows capture, control, DPI/multi-monitor behavior, permission failures and stop responsiveness remain unrun. GDI calls are synchronous OS calls; unlike the X11 transport, the candidate cannot impose a per-call cancellation deadline on them. Secondary-monitor selection and supplementary-plane Unicode input are not implemented.

## Remaining E03 scope

- Real bidirectional clipboard ownership/synchronization is **not implemented**; any `allow_clipboard` opt-in fails before opening a source/listener. Parsing and discarding ClientCutText is not clipboard support.
- Native macOS capture/control and a user-approved Wayland ScreenCast/RemoteDesktop portal source are **not implemented**. Selecting them returns a specific error and cannot silently fall back to host capture.
- Windows candidate native runtime qualification, secondary-monitor selection and cancellation qualification remain outstanding.
- Browser/HTTP port behavior and exact original TightVNC settings/access modes remain unresolved original-runtime evidence and implementation work. The original binary's 5900/5800/3600 resource strings are recorded separately; this candidate does not infer that all original options have been matched.
- Full integrated application tests and root independent review remain parent work. NFS and Cron are independent E03 requirements; this candidate does not claim their completion or change the overall 40/60 (66.7%) result.

## Protocol and API references

- [RFC 6143](https://www.rfc-editor.org/rfc/rfc6143): RFB message formats and the weak/classic security boundary. The server uses a bounded Rust implementation of the subset above and the existing DES provider, rather than launching or configuring a system VNC daemon.
- [x11rb 0.13.2](https://docs.rs/x11rb/0.13.2/x11rb/) and [XTEST ConnectionExt](https://docs.rs/x11rb/0.13.2/x11rb/protocol/xtest/trait.ConnectionExt.html): native X11 protocol provider.
- [Microsoft desktop capture sample](https://learn.microsoft.com/en-us/windows/win32/gdi/capturing-an-image), [GetDIBits](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-getdibits), [GetDC](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getdc), and [SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput): Windows candidate resource lifetimes and UIPI restrictions.

## Modifier review correction

The initial independent review found that both providers discarded character modifier requirements. `vnc-modifiers-native-red.log` records actual uppercase `A` arriving as lowercase `a` on the owned fixture before the fix. The Linux provider now reads the selected server's current XKB key types, modifier map, group and lock state; it chooses a character-producing key/level, temporarily changes only owned modifiers, restores explicit client modifiers per event, and releases owned character/modifier state on disconnect. It refreshes mappings for layout changes. It ignores a translation requiring release of an unowned physical modifier before changing any state. Windows uses literal Unicode for text without shortcuts and retains the target layout's VkKeyScanExW required modifier byte for Ctrl/Alt/Win shortcut input; native Windows execution remains unrun.

`vnc-modifiers-build.log` records 16 library passes with the isolated native case ignored in the ordinary run. `vnc-modifiers-native-green.log` is the explicit private Cage/bwrap replay: interpreted target-window characters use independent libxkbcommon over the fixture's actual map, covering uppercase/shifted punctuation without client Shift, explicit Shift restoration, Control/Alt shortcut state, CapsLock, a changed German layout and Euro/AltGr, and disconnect restoring the entire initial pressed-key bitmap. The existing wire, dynamic-pixel, application-client and independent vncdotool assertions are retained in this same native case. `vnc-windows-modifiers-component.log` and `vnc-x11-modifiers-component.log` compile the actual corrected providers; the two platform-independent Windows mapping tests also run in the library suite. `vnc-modifiers-ui-build.log` records four fresh UI unit passes (one native ignored); `vnc-modifiers-native-ui.log` records the explicit private Cage replay of the actual Servers Start/Stop pointer test against the newly built candidate.

The original review file identifies the superseded patch and remains historical evidence. A fresh parent-assigned independent review of the corrected patch is required before integration; this implementation note is not that review. Clipboard, macOS, Wayland portal, browser/HTTP viewing and native Windows qualification remain open E03 work. Overall progress remains 40/60 (66.7%); this private correction closes no parity item.

## Character-alias follow-up correction

The focused review in `vnc-review-fixes.md` identified one remaining alias mismatch: German EuroSign uses legacy keysym `0x20ac`, whereas clients can send Unicode keysym `0x010020ac`. `vnc-alias-native-red.log` records the real private Cage target failing to receive that Unicode form before correction. Character normalization now uses the already locked, exactly pinned pure Rust `xkeysym = 0.2.1` conversion. Both providers normalize character identity; X11 compares Unicode scalar values across its actual server map, and Windows passes the normalized UTF-16 value to its existing literal/shortcut planner. Function, modifier and keypad keysyms retain their identities. Mixed legacy/Unicode press/release pairs share held-key identity. X11 keyup uses the owned original keycode even after a layout change.

A valid character absent from the selected map is ignored before mutation, rather than treated as a capture/provider failure. This also preserves the no-release-of-unowned-modifiers boundary. The native fixture exercises both Euro encodings, both Greek alpha encodings on a real Greek map, mixed-encoding keyup and a valid unmappable rocket followed by successfully interpreted text, live framebuffer capture and Running status. Its final entire-keyboard bitmap assertion still checks disconnect cleanup. The prior A/#, explicit Shift, Ctrl/Alt, CapsLock, AltGr and independent vncdotool assertions remain in the same fixture.

`vnc-alias-build-green.log` records 17 library passes (one isolated native ignored), including the shared alias/function-identity and Windows planner regressions. `vnc-alias-native-green.log` records the explicit private native fixture. `vnc-alias-ui-build.log` records four UI passes (one native ignored); `vnc-alias-native-ui.log` records the fresh actual Servers pointer Start/Stop replay in private Cage.
