## Important finding

**Reject writable existing hard-link aliases before changing their inode.** At `src/services/nfs.rs:171–195`, a regular file with multiple hard links is accepted; `validate` at lines 145–159 compares path identity but does not reject additional links. WRITE at lines 469–499, SETATTR size at lines 398–427, and UNCHECKED CREATE size at lines 547–571 mutate the pinned inode in place. A regular file named inside the selected export can also have a hard-link name outside it. A client then overwrites or truncates the outside-named file despite the selected-root confinement contract. Disabling the NFS LINK procedure only prevents creating links through this protocol; it does not protect against existing aliases or aliases added later by local processes. This is distinct from authorized ordinary RENAME destination replacement.

The isolated [reproducer](nfs-review-hardlink.rs) opens a writable export containing `existing`, a hard link to `outside/secret`; NFS backend lookup/WRITE modifies the outside name and SETATTR(size=0) truncates it. [Completed probe output](nfs-review-hardlink.log): one test passed, proving the unwanted mutation, command exit 0. This is a behavioral backend proof against copied unchanged frozen source; it does not claim a new real-wire/native test. The fixture owns both temporary directories and makes no host configuration changes.

Apply a deliberate hard-link policy to existing and subsequently accessed regular-file handles before mutations, including UNCHECKED CREATE truncation. Conservatively rejecting multiple-link files is sufficient for the observed static alias; any stronger guarantee against arbitrary simultaneous local linking needs an explicit supported policy rather than a transaction claim. Add regression evidence for WRITE and both truncation paths preserving the outside file. Keep ordinary one-link existing-file updates and allowed POSIX rename replacement working.

## Reviewed behavior and limits

- Explicit absolute selected root, loopback/read-only defaults and separate non-loopback/write opt-ins are present. AUTH_SYS/AUTH_NONE use current-account permissions, with no OS impersonation or password/encryption claim; the Servers UI states this. Root/port work is queued through `supervisor.begin`; Stop only requests cancellation; status/log polling remains bounded. No added credential logs found.
- Names use byte-preserving Unix components; NfsName rejects slash/NUL/empty/overlong values and the adapter rejects dot/dotdot, backslash, colon and controls. Windows accepts UTF-8 names through its reserved-name policy. Cap-std parent traversal and final no-follow opens reject symlinks and special files. Generation plus retained descriptors/path identities reject cross-export/replaced/deleted handles. Hard-link aliases are the exception above.
- Size/offset arithmetic, transfer caps, creation/object/directory/depth caps and precharged incoming-write/growth budgets are present. EXCLUSIVE server-lifetime verifier retries and GUARDED creation are implemented. Directory cookies fingerprint sorted names plus mutation epoch; skipped inaccessible entries advance enumeration, including EOF on all-skipped tails.
- Read-only checks precede implemented mutations; unsupported VFS mutation defaults return ReadOnly or NotSupported. Chmod/chown/times, guarded SETATTR, LINK/SYMLINK/device creation, READLINK, NFSv2/v4, UDP and native-original equivalence remain explicit limitations. No full POSIX server or exact original protocol claim is supported.
- RENAME uses ordinary filesystem destination replacement in full-write mode. Target compare-and-swap against external edits is not promised and is not treated as a defect. Opened parent descriptors/no-follow path access retain the documented capability boundary; there is no transaction against arbitrary concurrent external renames.
- Listener owns a two-worker Tokio runtime. Configured admission, RPC fragment/record/buffer/replay/mount caps and client/request deadlines are finite. `Listener::serve` lines 46–54 explicitly signals shutdown and awaits `handle.wait()`. Pinned nfsembed 0.3.0 `server/handle.rs:62–72` retains the JoinHandle across cancelled wait futures; `server/mod.rs:334–348` drains or aborts/drains connection, auxiliary-service and execution JoinSets. Shutdown is therefore not merely a signal. Synchronous filesystem calls can still stall on adverse storage, as the implementation document correctly discloses.
- Cargo adds exact nfsembed 0.3.0 and async-trait 0.1.89 pins. Main lock reconciliation must resolve through the main package and must not copy the private `0.1.0-e03-nfs-private` package entry. Shared hooks touch existing service enum/supervisor/model/UI sites and need narrow reconciliation with Cron/VNC; the private final gap label must not overwrite the combined label.
