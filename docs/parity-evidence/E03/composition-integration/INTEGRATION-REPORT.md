## Parent-authorized intentional-Stop correction

ROOT explicitly authorized correcting Source-operation errors that race with observed Context cancellation. The original capture worker recorded any capture error as failure, so a cancelled asynchronous provider could make an intentional Stop appear Failed. The deterministic RED in `cancel-compose-red.log` proves that actual ServiceSupervisor state mismatch.

The parent expanded the ruling to all Source operations. One `source_failed` function now checks **actual Context.cancelled()**, not ErrorKind. All five Source failure branches (capture, clipboard poll/write, input, owned-input release) use it and exit the worker through normal Source Release cleanup. If cancellation is observed, no failure is recorded; otherwise the existing failure/status behavior remains. **Stop wins an observed service-status race.** A real error that wins the race before cancellation is observed remains Failed. Existing committed native actions are not undone and pending native buffers/blocks are not freed early. RFB authentication/protocol failures, arbitrary Interrupted errors, gateway policy, and unrelated RDP completion behavior were not changed.

`src/services/vnc/lifecycle_tests.rs` supplies a cfg(test)-only controlled source: startup returns a one-pixel owned frame, then a capture or clipboard poll blocks on an explicit gate and returns Interrupted. For both operations, actual supervisor Stop followed by release must reach Stopped with no error, execute Source Release and close both RFB/HTTP ports. Without actual cancellation, the identical Interrupted error must reach Failed. This exercises service ownership and state rather than mirroring a helper condition. Input/write/release branches share the same predicate, avoiding separate cancellation policies. No native API, clipboard, display or real permission is accessed.
