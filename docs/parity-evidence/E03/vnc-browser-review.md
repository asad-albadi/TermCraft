## Security and ownership assessment

- `src/services/vnc/browser.rs:15–39,171–175`: the gateway captures the owned RFB listener address during binding, normalizes wildcard RFB destinations to loopback and exposes no supplied target parameter. The only connect is to that captured address; queries and arbitrary asset paths do not select upstreams. HTTP binding on `0.0.0.0` uses the accepted stream's concrete local address for Host validation (`104–108`), so a wildcard is not incorrectly compared to an interface Host. IPv6 authorities use `SocketAddr` bracket formatting. Public reachability and cross-family/IPv4-mapped IPv6 behavior have not been demonstrated here.
- `browser.rs:59–188,204–307`: headers, methods, literal Host, exact same HTTP Origin for upgrade, version/key/upgrade tokens, duplicate/unsafe headers and request-body framing are checked before bridging. Paths are an embedded exact allowlist; there is no filesystem serving. CSP, no-store, nosniff and same-origin resource headers are set. Binary masked WebSocket frames are bounded to 1 MiB; unsupported frames, oversized controls and noncanonical lengths fail closed. Header/partial-frame/write/idle deadlines and bounded reads keep per-session memory/work bounded. Fragmentation and text messages intentionally remain unsupported. No arbitrary proxy capability or authentication bypass was found.
- `src/services/vnc.rs:67–116,183–221,329–374` and `src/services/supervisor.rs:490–550`: browser access is default-off; plaintext consent, non-loopback consent and mandatory classic-VNC password validation apply before startup. Existing RFB authentication, control and clipboard enforcement remain authoritative. Browser bind failure drops the newly owned RFB socket/source and preserves unrelated sockets. Both listeners share cancellation; gateway errors request cancellation, spawning failure joins the capture worker, and normal Stop joins gateway/client/capture ownership. The supervisor provides at most eight clients per listener (eight gateway sessions and eight RFB sessions, rather than one combined eight-client budget). No child process or runtime download is introduced.
- `assets/vnc-browser/viewer.js:1–26`, `index.html`, `src/ui/managed_vnc.rs`: the password is cleared from the input immediately and is passed only as in-memory RFB credentials. No URL, browser storage or log path receives it. Client view-only starts enabled; server controls remain authoritative when unchecked. HTTP/plaintext and lack of HTTPS are visible. Local wildcard links become loopback; remote users are told to use literal interface addresses. Managed configuration/status are in-memory structs, with no changes to serialized session models or legacy deserialization.
