# V01 SSH/SFTP matrix implementation checkpoint

`matrix.json` declares independent named InteropCase cells: endpoint, actual version source, authentication, host policy, gateway topology, operation, expected assertion, target test and exact test function. `scripts/check-ssh-interop.sh` builds selected binaries, executes each exact assertion separately, and writes an EvidenceRecord for every selected cell. The runner accepts only an exit-successful, nonignored, exactly-one-test result. Build failure, missing test, assertion failure and timeout remain failed outcomes. Run with `--case ID` to select a repeatable cell; an unknown selection is an error.

The matrix deliberately inventories existing extensive real transport coverage rather than cloning existing tests. `tests/ssh_interop.rs` checks coverage references and dimensions only; its two named checks are not endpoint success evidence. Actual interoperability evidence is the individually executed runtime test named in each matrix row. OpenSSH real daemon tests and russh controlled password/MFA fixtures are labeled separately. russh is pinned to 0.65.4 and russh-sftp to 4.0.0; `versions.json` captures actual installed OpenSSH, client, compiler and platform each run. The independent Dropbear 2026.94 endpoint uses a privately built, signature-verified upstream release. It observes pinned Ed25519 key auth, a shell marker and a 90,000-byte SFTP upload/download with literal quoted, Unicode and newline filename, using one authentication. Dropbear delegates SFTP to the installed external OpenSSH `sftp-server`; this is independent SSH transport interoperability, not an independently implemented SFTP engine. [Official release](https://matt.ucc.asn.au/dropbear/dropbear.html), signature/key provenance, exact archive and binary hashes and MIT notices are retained in `dropbear/`. Native Windows/macOS cells remain explicitly unavailable.

Private keys, agent sockets and passwords never enter retained evidence. The opt-in `TERMCRAFT_INTEROP_LOG_DIR` hook retains only owned OpenSSH stderr logs before the fixture removes its temporary root. Logs include endpoint identities and public key fingerprints. Controlled russh fixtures assert typed prompts and actual protocol events rather than fabricated successful results.

Run: `CARGO_BUILD_JOBS=2 scripts/check-ssh-interop.sh --output docs/parity-evidence/V01/runs/<run>` (or `python3 scripts/check-interop.py V01 ...`). The output contains per-cell logs and log hashes, per-cell test executable hashes, build log, versions and schema-compatible `evidence.json`. Exit status reports fixture failures; unavailable cells are visible in evidence even with an otherwise successful readiness run. A green exit code does not complete V01 parity.

Prepare the independent endpoint with `scripts/prepare-dropbear-interop.sh` (requires curl, GnuPG, C compiler and make). Everything stays below `target/interop-tools`; there is no host installation. The staging script verifies the pinned SHA256, detached upstream signature and official signing key fingerprint, and disables password/PAM plus all login accounting. Supported upstream `-D` selects only the owned key directory. It never modifies home SSH settings or the account database. The ordinary Rust suite explicitly ignores this optional prerequisite test; the matrix runner uses `--ignored` to execute it and still requires one actual passing assertion. An absent staged endpoint emits unavailable evidence. The default staged version path is a script-owned symlink under `target/interop-tools/dropbear/`. A custom `TERMCRAFT_DROPBEAR_DIR` must name `dropbear-2026.94` below this checkout’s `target/interop-tools`; unmanaged existing directories are refused and preserved. Every preparation freshly extracts the just-verified archive into an owned temporary stage, builds only there, then atomically replaces the managed symlink. Previous source/object trees are never executed or reused.

Missing native machines and paired original Personal 26.6 runtime evidence remain review gaps. No checklist or count is advanced by this implementation checkpoint.
