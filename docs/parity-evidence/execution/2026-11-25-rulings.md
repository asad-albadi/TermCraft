# Continuation decisions — 2026-11-25

These decisions preserve the approved full scope. Partial source implementations do not complete native/original parity.

- Ruling: use distinct private package versions AND binary names for shared build caches — package identity alone does not isolate the ordinary executable path. Cost if wrong: test artifact ambiguity; original identities must be restored in every delivered patch.
- Ruling: use a dedicated Linux Xephyr lease for XDMCP, with explicit all-interface/unencrypted consent — pinned Xwayland does not implement XDMCP. Cost: another pinned payload and additional dependency/packaging coverage.
- Ruling: qualify XDMCP through actual manager/cookie/window/ownership behavior without running an active RandR probe on the live remote session — resizing may affect its clients. Cost: X03 graphics qualification remains separately open.
- Ruling: permit TEST-NET networking only inside the opt-in user/network/PID fixture namespace — Xephyr excludes loopback from its advertised addresses. Cost: these tests require working private namespaces and confined NET_ADMIN.
- Ruling: keep native X server candidates disabled until patched native builds/checksums exist — the stock transports do not meet the owned/private listener contract. Cost: native source is present but the provider remains unavailable.
- Ruling: do not replace unavailable native XDMCP wiring with a hypothetical adapter — its safe listener and executable are not qualified. Cost: native XDMCP remains an explicit implementation gap.
- Ruling: privately build a signed independent Dropbear test endpoint instead of treating absent host installation as a blocker. Cost: another reproducible test-tool stage; its SFTP subsystem remains explicitly external OpenSSH.
- Ruling: Windows serial close must report the actual terminal result after cancellation retirement — completed writes must not be falsely reported aborted. Cost: a driver that never retires can retain its worker/resources; unsafe early buffer release is prohibited.
- Ruling: isolate PipeWire capture in an optional owned helper unless maintained dynamic bindings provide real optional loading — ordinary Linux/X11 startup must not acquire a mandatory libpipewire dependency. Cost: another helper protocol and package/source/license/dependency manifest.
- Ruling: accept a macOS14+ ScreenCaptureKit screenshot backend as the initial native capture implementation, bounded to one in-flight request and five frames per second. Cost: older macOS providers and stream-level performance remain open.
- Ruling: vendor the exact maintained ScreenCaptureKit bindings with only their strong framework link attribute removed; explicitly load the protected system framework after the OS guard and keep its handle alive. Cost: a small patch must be checked on binding upgrades; older-OS native linking/startup remains unverified.

- Ruling: count V01/V02 implementation checkpoints when reproducible runners and supported Linux matrices pass independent review and the merged gate; keep native/original observations unchecked. Cost: additional environments may reveal fixes, and this count must never be presented as full parity.

- Ruling: queue dependencies consume the existing qualified interface, not the full cross-platform checkpoint. Recovered catalog/source unblocks B06 implementation; available private desktop fixtures unblock V06; controlled Mosh network changes can proceed separately from absent serial hardware. Existing Linux X/package interfaces unblock further X/P08/V08 work despite missing native engine/distribution closure. Cost if wrong: a later native-specific task may need a narrower prerequisite; production engine/package gates are unchanged and no unavailable case can earn a checkpoint.
- Ruling: allocate private shared-target package identities centrally (UI0.1.607, V060.1.706) and refresh crate-root mtimes after verified source overlays. Cost if wrong: extra rebuild time; it prevents artifact reuse across private source roots or copied older timestamps. Superseded V060.1.606 pilot is not final evidence.

- Ruling: B06 includes Save/Load controls declared by the pinned game manual and recovered Sudoku help. Implement a bounded versioned TermCraft game file preserving board/history; original MobaXterm save/ID compatibility stays unverified. This is implementation of the approved full game-functionality scope, not a new approval milestone. Cost if wrong: an original-format adapter may be needed later; unknown engine versions must fail without replacing the active board or original file.

- Ruling: native smartcard Windows/macOS workers may use bounded framed anonymous inherited pipes rather than a literal UnixStream. The contract is packet bounds, private inherited endpoints and owned killable workers; pipes avoid Darwin datagram limits and TCP listeners. Cost if wrong: native runtime timing/inheritance qualification may require adapting transport; no native success is claimed. New private component lock initialization may use one offline Cargo generate-lockfile with two jobs; all actual checks remain offline/locked and existing MAIN dependency pins remain unchanged.
- Ruling: XDMCP bidirectional text clipboard mirrors every actual parent clipboard change into all explicitly enabled leases, including changes arriving from another enabled lease; suppress loops through origin/ownership/content generations, rather than suppressing those valid parent changes. Disabled leases remain isolated. Cost if wrong: additional protocol work; the earlier exclusion prototype is retained only as superseded evidence.
- Ruling: initial XDMCP engine/clipboard startup shares its caller deadline; a later steady-state server-reset recovery may establish one fresh bounded recovery deadline. All connect, authentication and endpoint setup steps within that recovery share the same absolute budget. Cost if wrong: a slow reset may fail explicitly; per-step renewal must not silently extend the budget.

- Ruling: Linux serial properties and COMMSTATUS may remain explicitly unsupported when the platform cannot establish the required capabilities, state and error-acknowledgment semantics. Unknown queue maxima are not encoded as zero because the protocol defines zero as unlimited. Implement additional events only from successful driver counters with a fresh logical-open/mask origin. Why: reporting invented success would mislead clients. Cost if wrong: a later device-specific provider can expose more capabilities, and D02 remains partial meanwhile.
- Ruling: the next local validation batch must include a real portal backend inside an owned headless compositor, not relabel the existing mock-portal transport fixture as native behavior. Fixture consent automation is limited to that isolated desktop; the product never accepts consent on behalf of users. Why: the missing backend can be provisioned privately on this machine. Cost if wrong: additional fixture setup/rework; no host screen or input is exposed.
- Ruling: XKB variants/groups and IPv6 remain explicit limitations and conditional scope until exact Personal evidence establishes them as parity requirements; single layout IDs and required Direct/Indirect paths are implemented. Why: do not expand the approved X04 outcome based on stale queue language. Cost if wrong: original-runtime comparison can reopen these implementation tasks.

- Ruling: allow an optional positive Debian packaging revision while preserving the upstream Cargo/application manifest version and current default packaging behavior. Why: old and current genuine artifacts are both0.1.0, so same-version reinstall alone cannot demonstrate a monotonic package upgrade. The native packaging task will generate and verify the real revision metadata, not edit compiled versions or relabel old payloads. Cost if wrong: packaging CLI/file naming may need adjustment; no public release or user installation is performed. Private source patch must receive independent review before integration.
