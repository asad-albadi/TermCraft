# D02 native local-printer design and scope

This private source increment extends the existing explicit legacy RDPDR mapping to Windows Winspool and Darwin System CUPS. Saved fields/defaults remain the same: `printer_mapping: None` grants no queue access, and queue/remote-driver strings remain user choices. No queue discovery, default-printer lookup, remote-server syntax, conversion, Easy Print or XPS negotiation is added. An explicitly selected installed local queue can already have a network backend configured by its owner. No physical printing was performed.

## Source-grounded decisions

The design uses the published contracts below, rather than inferring driver or queue metadata. Sources were consulted before their corresponding implementation choices; this document records the decisions for review.

- Microsoft [OpenPrinter/OpenPrinter2](https://learn.microsoft.com/en-us/windows/win32/printdocs/openprinter) documents `PRINTER_ACCESS_USE`, the non-thread-safe HPRINTER and potentially blocking no-cache access. A single child process owns one retained HPRINTER opened by `OpenPrinter2W` with `PRINTER_OPTION_NO_CACHE`, using the selected local queue only. The parent never opens Winspool. Certificate retries retain this process/handle; failures poison it instead of reopening a name.
- [GetPrinter](https://learn.microsoft.com/en-us/windows/win32/printdocs/getprinter) levels 6/2 supply status and the selected queue's print processor. [EnumPrintProcessorDatatypes](https://learn.microsoft.com/en-us/windows/win32/printdocs/enumprintprocessordatatypes) checks that processor for RAW before announcement. Returned variable buffers/pointers are aligned and bounded to 256 KiB. Direct-output queues are refused because AbortPrinter has no spool to remove there.
- [StartDocPrinter](https://learn.microsoft.com/en-us/windows/win32/printdocs/startdocprinter) returns the owned job ID. `DOC_INFO_1W` supplies RAW and no output filename. [WritePrinter](https://learn.microsoft.com/en-us/windows/win32/printdocs/writeprinter) is checked for failure, zero progress and partial progress. [EndDocPrinter](https://learn.microsoft.com/en-us/windows/win32/printdocs/enddocprinter) is acceptance, not physical output. [AbortPrinter](https://learn.microsoft.com/en-us/windows/win32/printdocs/abortprinter) is used only for the current document on that HPRINTER. No `SetJob` cancellation by a possibly reused job ID is issued after acceptance. Winspool is synchronous and belongs in the killable child.
- The ABI is provided by `windows-sys 0.61.2` generated Winspool definitions, with Printing/Gdi/Security features. [Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects) confine helper lifetime with kill-on-job-close. Assignment happens before the first queue initialization frame, so the child cannot call Winspool before ownership is established.
- Apple's [cupsd launch configuration](https://github.com/apple/cups/blob/master/scheduler/org.cups.cupsd.plist) names `/private/var/run/cupsd`; [xcode/config.h](https://github.com/apple/cups/blob/master/xcode/config.h) defines this domain socket. The Darwin provider uses the local service's IPP API on this fixed socket. It verifies root ownership, non-symlink socket, protected directory ancestors, and root peer credentials; Apple's [unistd.h](https://github.com/apple-oss-distributions/Libc/blob/main/include/unistd.h) defines `getpeereid`, used by Tokio's native peer-credential API. It retains the connected socket, without Linux O_PATH, `/proc`, per-user CUPS settings, libcups auto-reconnection or network fallback.
- Apple's [CUPS IPP specification](https://apple.github.io/cups/doc/spec-ipp.html) and [IPP implementation headers](https://github.com/apple/cups/blob/master/cups/ipp.h) ground Get-Printer-Attributes and Print-Job. The existing bounded raw IPP codec is retained. The Darwin HTTP connection stays open; a disconnect/restart fails closed, rather than reconnecting by path. Queue readiness additionally records `printer-uuid`; a changed or missing UUID refuses subsequent retries/submission. IPP has no atomic UUID precondition on Print-Job: a privileged local administrator can replace a queue between this check and submission. The local spooler administrator remains trusted; this is not an atomic native queue-object lock. The configured remote driver is announced unchanged and never guessed from CUPS or Winspool metadata.

## Ownership, cancellation and limits

The existing shared PDU frontend still owns at most four anonymous spool files of at most 32 MiB each and accepts at most 64 KiB per wire write. Wire FileIds increase without reuse. Driver strings, remote paths and cache metadata do not create additional local authority. View-only and installed-client restrictions remain enforced. The Linux provider retains its original O_PATH socket identity and controlled IPP tests.

A native mapping creates one private actor thread/runtime and one owned helper process. Its request channel has capacity one and frames are capped at 65,537 bytes. A global budget admits at most sixteen native helper actors. Each readiness call and entire submission has a ten-second deadline. Native methods execute only inside the helper, outside the UI and RDP loops; each helper has one active document. Parent filesystem spooling retains the existing bounded device-worker behavior and local-storage responsiveness limitation.

Dropping a pending call, timeout or channel cancellation permanently poisons that helper. Parent cleanup closes its input, allowing an idle helper to abort only its active document. It waits at most 250 ms; after an owned-child liveness check, it requests process termination and bounds reaping to two seconds. It does not join a driver thread. Only `Ok(Ok(exit_status))` proves reaping. A wait error is unknown identity evidence and never permits signalling a Unix PID; a timeout permits termination only after `try_wait` confirms that the owned child remains live. An ambiguous final wait retains the child, budget permit and Windows ownership handle without running kill-on-drop. Repeated failures therefore cannot create unlimited driver processes. Windows JobObject ownership closes on parent death; Darwin's child watchdog exits if its parent changes. No global spooler/CUPS service is stopped. In-flight driver buffers remain child-owned until the OS destroys the process.

A cancelled partial pipe write must never be followed by an Abort frame: the remainder might become print bytes. Cleanup therefore uses EOF/termination. The helper's own protocol validates exact operation shapes and remaining document length, aborting its current owned document after malformed requests or EOF. A failed initialization preserves its native NTSTATUS-style permission/not-found/error code through the real framed pipe.

## Honest cancellation boundary

Abort is best effort. Bytes already physically printed cannot be recalled. Windows may have accepted/output bytes before EndDocPrinter/AbortPrinter or process termination; a failed abort can leave a queued document. Darwin closes its own incomplete upload; once the full Print-Job has reached CUPS, CUPS may accept or print it even if the confirmation is lost. Accepted/ambiguous jobs are not retried automatically or cancelled using stale queue/job IDs. The UI advises checking the explicitly selected queue before retrying. No success completion claims paper output.

## Evidence boundary

Linux controlled tests exercise the shared PDU limits, existing real IPP socket traffic, retained-stream response/UUID parsing, native-helper framing, real pipe status mapping, and poisoning/termination/reaping of an owned intentionally hung fixture process. Rust component checks compile the exact native provider sources for `x86_64-pc-windows-msvc` and `aarch64-apple-darwin`. These checks are not native SDK link checks, native spooler runtime tests, remote Windows driver-negotiation tests, or hardware output tests. Those remain pending; D02 remains open.
