## Important findings

1. **Use the asynchronous count-pointer contract at native dispatch.** `engines/rdp/src/serial_windows.rs:266`, `:273`, `:280`, `:290`: `Pending::new` passes the address of its local `transferred` variable to overlapped ReadFile, WriteFile and DeviceIoControl, then discards that count and may return while I/O remains pending. Microsoft's ReadFile and WriteFile documentation directs asynchronous callers to use a null count pointer; DeviceIoControl permits null with an OVERLAPPED and directs callers to GetOverlappedResult for the eventual count. Remove this unused local and pass `std::ptr::null_mut()` at precisely those three arguments. Keep local count variables in the synchronous GetOverlappedResult calls. This is a concrete asynchronous API-contract issue; no native execution or demonstrated memory corruption is claimed. Acceptance: source inspection of the three arguments plus both native component checks; preserve actual terminal counts from GetOverlappedResult. [ReadFile](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-readfile), [WriteFile](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-writefile), [DeviceIoControl](https://learn.microsoft.com/en-us/windows/win32/api/ioapiset/nf-ioapiset-deviceiocontrol).

2. **Close fabricates cancellation without checking the terminal native outcome.** `engines/rdp/src/serial_windows.rs:408`–`:410`, with retirement at `:336`–`:344`: close first queues CANCELLED for each matching Pending, then its destructor requests cancellation and waits while discarding the terminal result. A write or mutating control can already have completed successfully before this worker handles close, or win the cancellation race. It is nevertheless reported cancelled. CancelIoEx explicitly permits normal completion, aborted completion, or another failure, and requires checking the completion status. For example, a write that completed while close was queued can return CANCELLED instead of its successful byte count. Add an explicit cancel-and-retire path for close that requests cancellation, awaits native completion while retaining the buffers/event/handle, then constructs the completion from the actual outcome; reserve Drop for cleanup when no protocol response can be delivered. Acceptance: a bounded pure test of terminal-result mapping covering success with byte count, ERROR_OPERATION_ABORTED, and another native failure; retain native close/cancellation runtime testing as unrun. [CancelIoEx](https://learn.microsoft.com/en-us/windows/win32/api/ioapiset/nf-ioapiset-cancelioex), [GetOverlappedResult](https://learn.microsoft.com/en-us/windows/win32/api/ioapiset/nf-ioapiset-getoverlappedresult).

## Reviewed safeguards and remaining limits

Windows serial pins a selected COM endpoint in the binding and retains it across retries/remote reopen. Read-only mappings and handle permissions guard mutating dispatch; control codes and buffers are explicitly bounded. OVERLAPPED is boxed, buffers retain their allocations, the event is owned, and each Pending retains the device handle. Cleanup requests cancellation and waits on the device worker before freeing those resources; serial teardown drains Pending before restoring the handle's DCB/timeouts. A noncompleting driver can retain that worker and device resources, while UI/protocol tasks do not join it. Native timing, cancellation responsiveness, physical-port state restoration and unplug behavior remain unexecuted. The 16 outstanding-request limit plus reserved close slot and 64 KiB I/O cap bound a channel's admitted operations; this review does not claim a process-wide cap on stuck workers.

Windows file mutation uses the opened regular-file source. Rename resolves a confined capability directory and validates one leaf, rejecting separators, streams, NUL, dot components and trailing space/dot before using RootDirectory. Replace/no-replace is passed explicitly to the native API. DELETE authority and root read-only policy gate rename/disposition; file allocation checks write authority. Full FileIdInfo preserves 128-bit identity. Directory rename/delete, delete-on-close and Linux/POSIX identity-unsafe path mutations remain unsupported. Native destination conflicts, replacement, permissions and source/path replacement fixtures are compiled only. [FILE_RENAME_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_rename_info).

Darwin preallocation operates on the opened file, requests the physical-allocation deficit, preserves logical EOF when growing allocation, and omits F_ALLOCATEPERSIST so native close can release unused allocation. The extra Reservation handle retires with its shared handle lifetime; Linux alone performs explicit hole-punch cleanup. The Darwin allocation/close fixture is compiled only, so actual close cleanup and filesystem behavior remain unverified.

Unix reads retain request-time timeout settings and start deadlines when their direction can run. Byte accumulation, interval/first-byte/immediate modes, writable-only mutation checks, explicit unsupported modem/handshake cases and restoration flags were inspected. Original termios is restored on close, changed break/flow state is cleared/resumed, and supported changed modem bits are restored without taking over kernel-owned RTS. The owner PTY results do not establish physical modem/flow parity.

Windows/macOS printer and smartcard providers, missing serial event/control families, full Windows helper packaging/linking, native volume/directory allocation details, original-product comparison and native RDP interoperability remain open as stated in the handoff README.
