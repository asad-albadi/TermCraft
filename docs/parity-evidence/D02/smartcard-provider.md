# D02 embedded RDP smartcard provider

Linux embedded RDP can redirect one explicitly named local PC/SC reader. The default opens no smartcard provider or RDPDR channel. The installed Windows client retains its existing automatic smartcard setting. Embedded sessions reject that legacy automatic setting, and view-only configurations reject redirecting a reader.

The helper establishes a temporary PC/SC context to check that the exact reader is present, then releases that context. A missing service or reader prevents the device announcement. The embedded RDPDR channel requires the peer's smartcard capability, advertises capability version 1, and announces a single type `0x20` device named `SCARD` with empty device data. Drive, serial, and printer IDs occupy earlier positions on the shared channel. The reader name is sent to the peer only as part of the selected reader's smartcard responses. [MS-RDPEFS capability header](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-rdpefs/b3c3304a-2e1b-4667-97e9-3bce49544907) and [device announce header](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-rdpefs/32e34332-774b-4ead-8c9d-5d64720d6bf9).

The worker opens a canonical absolute `libpcsclite.so.1` path from conventional Linux system library directories. The candidate and resolved paths must have root-owned entries and no writable non-root components. Both child launch boundaries remove dynamic loader and PC/SC override variables without changing the parent environment. Its `LONG`, `DWORD`, handles, PCI structures, and reader-state layout follow the native headers, including machine-word widths on 64-bit Linux. The worker accepts MS-RDPESC IOCTLs for readiness, context establishment, validation and release, reader groups and list, status and cancellable reader watches, connect, disconnect, transaction begin/end, and T=0/T=1 transmit. It translates native status bits to the Windows status enumeration and keeps native handles private behind per-session tokens. The supported Unicode calls carry UTF-16 reader names, while ANSI reader names are limited to ASCII. Assigned controls outside the implemented subset return an explicit status. Unassigned codes drop before taking a worker slot or making a native call. [MS-RDPESC IOCTL processing](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-rdpesc/60d5977d-0017-4c90-ab0c-f34bf44a74a5), [MS-RPCE private header](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-rpce/63949ba8-bc88-4c0c-9377-23f14b197827), [pcsc-lite API](https://pcsclite.apdu.fr/api/group__API.html), and [pcsc-lite ABI types](https://pcsclite.apdu.fr/api/wintypes_8h.html).

A private bounded Unix socket carries device requests to an owned helper subprocess. Native device operations run there, and the RDP task polls the socket without blocking. An active native stall has a four-second watchdog. The worker tracks at most sixteen outstanding requests, sixteen contexts, sixteen card handles, and eight pending status watches. A status watch can remain pending while other requests proceed. Successful cancellation or release resolves watches only on the requested owned context. A transient native failure leaves its watches active. Transmit validates the full padded response capacity before dispatch and preserves the caller’s native receive capacity. Closing the session kills and reaps the owned worker even if a native call is stalled. Linux parent-death signalling covers abrupt helper termination. Application-owned sensitive buffers are wiped on release. The underlying IronRDP and TLS library buffers retain their own allocation lifecycles.

## Evidence

- The root options test first failed on the missing `smartcard_reader` field. The private process entry test first failed because the worker argument entered the main desktop protocol. The updated root RDP options suite passed 12 tests.
- The current helper suite passed 41 unit tests and eight integration test entries, including the private fixture entry. These cover the disabled channel, capability and announcement bytes, unconfigured reader refusal, Unicode enumeration of only the chosen reader, native status, card exchange with optional receive PCI, malformed NDR and stale handles, isolated cancel, watchdog expiry and reaping during a deliberately stalled native transmit, failed native cancellation and release, exact transmit frame sizing, and unassigned control floods.
- The sealed-memory probe from the initial implementation verified self-execution of the PC/SC subprocess through `/proc/self/exe` by observing a real X.224 request on a private loopback listener. The hardened launch test installs a harmless executable under a checksummed fixture manifest and confirms through the sealed command that inherited-variable overrides are absent.
- The private C fixture loads by absolute path only in the spawned integration-test harness. That harness verifies loader override removal at the worker launch. The production executable has no fixture selection path. It uses separate native contexts and card handles and returns a synthetic response through the same RDPDR wire and process transport as the production worker. The fixture also passed a syntax check against the installed pcsc-lite headers with warnings treated as errors.

```sh
CARGO_BUILD_JOBS=2 cargo test --offline --locked --manifest-path engines/rdp/Cargo.toml
CARGO_BUILD_JOBS=2 cargo test --offline --test rdp_options
CARGO_BUILD_JOBS=2 cargo test --offline --lib rdp_helper_launch_removes_loader_overrides
cc -DVERIFY_PCSC_HEADERS -I/usr/include/PCSC -fsyntax-only -Wall -Wextra -Werror engines/rdp/tests/fixtures/pcsc.c
```

## Open coverage

The host had the native pcsc-lite library but no default PC/SC daemon socket. System reader and physical-card validation was unavailable. The fixture validates the PC/SC ABI and RDPDR packet exchange without a physical card or Windows RDP server. An attempted Windows-target helper check stopped while compiling the existing `libz-sys` dependency because the local compiler is incompatible with the MSVC target. Windows uses a distinct WinSCard ABI, and Apple's PCSC headers use fixed-width types. [Windows smartcard PCI definition](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/winsmcrd/ns-winsmcrd-_scard_io_request) and [Apple SmartCardServices headers](https://github.com/apple-oss-distributions/SmartCardServices/tree/main/src/PCSC).

Native Windows RDP interoperability, embedded Windows/macOS PC/SC providers, physical card/PIN workflows, smartcard credential/NLA logon, raw reader control, extended attributes, reconnect, card cache, and full MS-RDPESC coverage remain open.
