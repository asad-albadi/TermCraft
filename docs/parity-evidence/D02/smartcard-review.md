# D02 Linux smartcard provider review

**Disposition.** Keep D02 open. Static review identified three important issues. No critical finding was established. The review used source inspection, Microsoft’s published protocol, and a successful independent C syntax check against the installed Linux PC/SC headers.

## Important findings

1. **The packaged worker inherits library search overrides.** At `engines/rdp/src/smartcard/pcsc.rs:108` the worker opens a bare soname. At `engines/rdp/src/smartcard.rs:135` the launch inherits the local environment with only the PC/SC debug variable removed. The sealed launcher at `src/runtime/manifest.rs:150` protects the executable image only. The private fixture at `engines/rdp/tests/pcsc_worker.rs:41` selects its provider using this same loader behavior. An inherited local search path can therefore select code that handles card traffic. The RDP peer has no demonstrated control over this environment. Sanitize loader overrides at both production exec boundaries and keep fixture injection explicit. Acceptance check: inspect the environment delivered by the packaged launch using a harmless child that reports only presence/absence of loader override names. Verify the private fixture still works through the designated test path.

2. **Transmit silently shortens the caller’s native receive buffer.** At `engines/rdp/src/smartcard/session.rs:683` a non-null receive buffer is clamped to the outer response frame even when the caller explicitly requested a larger one. A native driver can execute a state-changing command and subsequently return insufficient buffer, leaving the caller unable to determine whether retrying is safe. Preserve the requested receive capacity within the supported maximum, or reject inconsistent frame sizing before dispatch. Acceptance check: give the existing private C fixture a transmit-call counter. For an inconsistent frame, assert a framing error and zero native transmit calls. Cover both receive-PCI layouts and exact-fit padding. [MS-RDPESC Transmit_Call](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-rdpesc/e3861cfa-e61b-4d64-b19d-f6b31e076beb)

3. **Cancellation and release retire watches even after native failure.** At `engines/rdp/src/smartcard/session.rs:382` and line 389, both operations set the retirement flag unconditionally. A failed release retains the live context but completes its watches as cancelled. Make watch retirement conditional on successful native cancellation/release, or handle specifically documented terminal native errors explicitly. Acceptance check: have the private fixture return a transient error for each operation in turn. Verify that its error reaches the caller and that the same live context’s watch can still complete normally afterward. The existing successful cancellation check covers isolation between contexts. [MS-RDPESC processing rules](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-rdpesc/60d5977d-0017-4c90-ab0c-f34bf44a74a5)

## Additional protocol divergence

The invalid-control path at `engines/rdp/src/smartcard/session.rs:143` and line 360 emits an unsupported completion for unassigned control codes. The protocol requires dropping an invalid control. Distinguish unassigned codes from valid but unimplemented operations and account for a locally dropped request without leaving its completion ID pending. [MS-RDPESC processing rules](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-rdpesc/60d5977d-0017-4c90-ab0c-f34bf44a74a5)

## Coverage and limits

The code uses Linux machine-word handles and PCI fields, exact reader matching, context-scoped card maps, bounded worker queues, a readiness deadline, an owned child kill/wait path, and zeroizing buffers on the inspected application APDU path. Root options and the embedded and installed-client paths distinguish named-reader redirection from automatic redirection. Library-owned copies have separate lifetimes. The integration fixture compiles its own typedefs by default. The independent header check used `cc -DVERIFY_PCSC_HEADERS -I/usr/include/PCSC -fsyntax-only -Wall -Wextra -Werror engines/rdp/tests/fixtures/pcsc.c` and passed.

The provider record reports 41 helper unit tests, four private worker integration tests, 12 root options tests and an X.224 request from a sealed helper. This review did not rerun those suites. The earlier 554-test root run predates the provider. A newer full gate is pending. Windows packaging/linking, native Windows RDP interoperability, physical cards, PIN entry and smartcard NLA remain unverified. The previously reported Windows-target dependency/toolchain failure supplies no successful Windows build evidence.


## Fix evidence

- The packaged, checksum-verified helper command and the PC/SC child command share the same launch sanitization. The sealed-package test runs a harmless child that checks only environment variable presence. The worker tests verify the same boundary while passing the C fixture through a test-only absolute path, with no fixture selection in the packaged executable. The Linux provider restricts its library selection to canonical paths from root-owned system locations. The PC/SC delegate variable is removed at both launches. [pcsc-lite delegate loader source](https://pcsclite.apdu.fr/api/libredirect_8c_source.html)
- Both transmit layouts are checked using an outer frame one byte short of the required padded size and then an exact-fit frame. The short case returns `STATUS_BUFFER_TOO_SMALL` with zero new native transmit calls. The exact-fit case calls the native fixture once.
- The fixture independently returns a transient error from cancel and release. In each case the error is forwarded to the caller and the same watch completes normally after a fixture state change. The successful cancellation and wrong-context checks still pass.
- A burst of 200 unassigned controls drops before queue admission, produces no completion and leaves the first completion ID available for valid work. An assigned unimplemented control still returns `STATUS_NOT_SUPPORTED`.

The three protocol regressions and the launch environment regression failed before the fixes. The current verification passed 41 helper unit tests, eight helper integration test entries, 12 root RDP options tests, and the sealed-package environment test. The fixture also compiled against the host's PC/SC headers with warnings treated as errors. Independent rereview and native interoperability coverage remain open.

## Follow-up review of the four findings

1. **Loader overrides — ADDRESSED.** The desktop helper and its PC/SC child both apply the shared environment cleanup before execution. Production resolves the provider to an absolute system path and checks ownership and permissions for the package entry, canonical target and their ancestors. The alternate provider entry is restricted to the test build. See `src/desktop/mod.rs:665`, `engines/rdp/src/smartcard.rs:161` and `engines/rdp/src/smartcard/pcsc.rs:135`. The reported sealed-helper environment probe and private fixture cover the two process boundaries.
2. **Transmit receive capacity — ADDRESSED.** The provider checks the rounded response size, including optional receive PCI, before a native call and preserves the caller’s bounded receive capacity. The private regression checks the native call counter at the exact fit and one byte below for both PCI layouts. See `engines/rdp/src/smartcard/session.rs:665` and `engines/rdp/tests/pcsc_worker.rs:371`.
3. **Failed cancellation or release — ADDRESSED.** Watch retirement now requires native success. The private regression checks each failure independently and verifies that the original watch subsequently reports a state change. See `engines/rdp/src/smartcard/session.rs:388` and `engines/rdp/tests/pcsc_worker.rs:397`.
4. **Unassigned control codes — ADDRESSED.** The worker drops unassigned control codes before adding a completion ID to its pending set. Valid unimplemented controls retain their separate error path. The regression checks that a subsequent valid call can reuse a dropped ID and that an assigned, unsupported control returns its error. See `engines/rdp/src/smartcard.rs:192` and `engines/rdp/tests/pcsc_worker.rs:427`.

The follow-up inspected the corrected source and regression assertions. The implementation run reported 41 helper unit tests, eight helper integration tests, 12 root options tests, the sealed-helper probe, the C header check and formatting passing. Native Windows RDP interoperability, physical cards, PIN and NLA remain open.
