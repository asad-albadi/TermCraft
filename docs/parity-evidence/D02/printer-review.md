# D02 Linux legacy printer review

The initial review raised three Important findings. The follow-up below records their resolution. The retained helper test executable passed all 35 tests in this review. The provider evidence records eight printer fixtures and an isolated CUPS 2.4.20 backend delivering the 45-byte fixture with a matching hash. This review used no physical printer or host CUPS writes.

| Priority | Source | Finding and regression expectation |
|---|---|---|
| Important | `engines/rdp/src/printer.rs:280`, `:295`, `:300`, `:311` | A failed write discards its spool and immediately frees its wire FileId. A concurrent document can inherit that ID before the original close arrives. The old close can then submit the new document prematurely. Give new jobs distinct wire IDs independently of the four-open-spool limit. Exercise overlapping documents with a write failure and delayed original close. The original close must leave the second spool intact and the sink must receive only the complete second document on its own close. |
| Important | `engines/rdp/src/printer.rs:54`, `:65`, `:122`; `engines/rdp/src/devices.rs:776`, `:943` | A socket inode with the expected owner is enough to advertise a printer. Checking for a listener, authenticating its peer, and contacting the queue currently wait until submission. A stopped daemon with a stale socket or a misspelled queue is therefore presented as available. Perform a bounded read-only check for the explicitly selected queue and its raw document format before announcement, using the pinned endpoint. Test a stale owned socket, a missing queue, and a ready queue. The first two should give actionable setup failures, and the ready queue should be the only announced printer. |
| Important | `engines/rdp/src/printer.rs:213`–`226`; `engines/rdp/src/printer_tests.rs:78` | A matching IPP header and final delimiter suffice for a successful RDP close. The success fixture actually omits every attribute, including the required job ID. This permits an invalid or truncated attribute structure ending in the delimiter to be reported as acceptance. Decode the bounded attribute groups and validate a successful Print-Job response. Use a standards-conforming fixture plus incomplete attribute groups and absent job identification. Malformed replies must report failure without automatic resubmission. [IPP Print-Job response requirements](https://www.rfc-editor.org/rfc/rfc8011#section-4.2.1.2) |

The reviewed path pins the Unix socket before certificate negotiation, checks the connected peer at submission, validates the selected queue, and sends the configured driver only in the device announcement. The spool uses anonymous files and enforces per-write, per-job and open-job bounds. Ordered processing, a fixed HTTP body length, and cancellation during upload protect ordinary disconnects. The ten-second submission timer covers asynchronous socket activity. Synchronous filesystem operations depend on local storage responsiveness. A completed upload can already belong to CUPS when the transport disconnects.

Native Windows driver negotiation, Easy Print, Windows and macOS local providers, smartcards, and physical output remain outside the observed evidence. D02 stays open.

## Follow-up

- Printer wire handles increase for each open job and never wrap or recycle within the worker. The four-open-spool limit is independent of handle allocation. The regression test fails the first document's write, opens a second document, sends the delayed first close, then verifies the second document reaches the sink in full on its own close.
- Before attempting each RDP connection, the helper sends a bounded, read-only Get-Printer-Attributes request to the pinned local CUPS socket. It checks connected peer credentials and verifies the selected queue URI, readiness for jobs and raw document format. A stale socket, missing or mismatched queue, stopped acceptance, and unsupported format refuse setup with a queue-specific message. The retry fixture swaps the visible socket path and verifies both the readiness probe and document still reach the original socket.
- The HTTP response and IPP groups are decoded within fixed bounds. Print acceptance requires the requested version and request ID, valid operation and job attribute groups, a positive job ID and matching CUPS job URI, and valid job state and reason attributes. A returned printer URI must match the selected queue. Missing, truncated and mismatched replies fail the remote close and surface an unconfirmed-job message. They never resubmit automatically.
- All three behavioral regressions reproduced against the prior provider. The refreshed helper suite includes twelve printer fixtures. The isolated CUPS 2.4.20 run completed the actual readiness probe with an empty print spool, then accepted a real Print-Job and forwarded all 45 bytes to an owned loopback sink. The spool and sink SHA-256 both matched `da84987873369534a02c2f86ba3130cd00dfa720b2b0cb813a1b99fe7bc562f3`. The isolated daemon and sink were retired without changing system queues. Native Windows driver negotiation and physical output remain unverified.

### Independent re-review

All three original findings are **addressed**. New wire IDs cannot reuse retired handles. Each connection attempt checks the selected queue on the pinned socket before announcing it. IPP success now requires a bounded, structurally decoded reply identifying the accepted job. The independent locked offline helper rerun passed all 39 tests, including all 12 printer fixtures. The native CUPS result above comes from the recorded isolated run.
