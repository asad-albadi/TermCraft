## Load-bearing review conclusions

1. **Native ownership and stable storage:** Session, held by the shared dispatcher, contains channel endpoints and logical state only. Handle and every Pending are constructed inside run_owner after spawn. OVERLAPPED is boxed; Vec allocations, event, and Arc<File> survive native cancellation until GetOverlappedResult reports the terminal outcome. Successful output is borrowed/transformed only after that terminal result; failed output is not interpreted. Movement into the pending deque does not move the buffer/OVERLAPPED allocations. Native pointers do not reference the request clone or a temporary output buffer.
2. **Owner lifetime, cancellation, and unwind:** The owner loop remains alive while native requests remain incomplete. Cancellation is requested once per Pending, never treated as completion. Explicit CLOSE polls actual outcomes and sends each operation response before the successful close result. A write which beats cancellation remains successful; a native aborted read remains aborted. On disconnection the bounded owner retains its state until retirement. On unwind, pending was declared after handle, so its Drop fallback retires outstanding I/O on the issuing thread before Handle restoration. The outer closure retains its permit while run_owner unwinds. The remaining blocking GetOverlappedResult(TRUE) is confined to this dedicated-owner fallback; Session/Serial destruction does not call it or join a thread.
3. **Capacity and quarantine:** OwnerPermit atomically reserves shared binding exclusivity and one of sixteen process slots before spawn/native initialization. Spawn failure drops the captured permit and returns a resource failure. Both flags remain held through initialization, pending retirement, probe retirement, and state restoration. A stalled owner occupies bounded resources and prevents cloned bindings/certificate retries from reopening that binding. The separate inherited optional-probe mechanism has its own sixteen-slot cap; this does not accidentally create an unbounded pool.
4. **Probe linkage and reopen ordering:** The optional probe owns its file and native stack/event storage independently. Dropping Probe abandons adoption and requests cancellation; it does not release its native retirement permit early. Handle::drop waits for that shared probe_busy flag before restoration. Therefore a late probe cannot race restoration/reopen even after the 100ms adoption deadline. Each native GET_STATS request captures its current logical origin, and late baseline results cannot be adopted by a later logical open.
5. **Admission, close escape, and bounded results:** Request admission is try_send into eighteen slots and preserves the rejected request ID in its busy result. Native admission allows sixteen ordinary requests and one additional valid SET_WAIT_MASK escape; CLOSE does not need a Pending slot. The unchanged outer Channel admission was inspected: sixteen general credits, a seventeenth wait-mask escape, and eighteenth CLOSE credit bound actual connection-wide outstanding requests. Thus direct fixture calls that can fill eighteen ordinary queue slots bypass the production admission rule; they demonstrate the nonblocking queue fallback, not the production reservation policy. The nineteen-slot event queue is bounded; only the owner may block sending events. Serial::ready drains events before forwarding them to the shared results queue. No new shared-worker native wait was found.
6. **Ordering and fair shared dispatch:** CREATE initialization runs asynchronously. The explicit opening FIFO publishes successful IDs only when their successful CREATE response is emitted, retains ordering across ports, rejects duplicate opens, and rejects guessed/unpublished IDs. Failed asynchronous opens can consume monotonic IDs; this matches the stated ruling. Owner command work is capped per poll, then cancellation/completion polling progresses. Shared dispatcher filesystem/other-device work does not enter an owner's native wait. A stuck first CREATE intentionally delays later CREATE replies to retain the required admission order.
7. **Restoration:** Pending outcomes retire before Handle destruction. State/mask restoration is owner-local, and permit/binding release follows that restoration before Closed is sent. A blocked restoration quarantines the owner/binding without blocking the shared dispatcher. Bind-time CreateFileW/GetCommState remain inherited setup calls outside the shared-worker guarantee, as explicitly scoped.
