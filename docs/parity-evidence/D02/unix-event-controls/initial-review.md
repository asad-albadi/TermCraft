# D02 Unix serial controls review

SPEC CHANGES. QUALITY CHANGES. Two actionable findings in the reviewed payload.

1. Candidate engines/rdp/src/serial.rs:78–91, 195–196, 708 returns absolute TIOCGICOUNT values for GET_STATS. Microsoft defines each SERIALPERF_STATS field as the count “since either the serial port was opened or the last IOCTL_SERIAL_CLEAR_STATS request was processed” ([SERIALPERF_STATS](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntddser/ns-ntddser-_serialperf_stats)). The logical remote CREATE only clones a descriptor that bind_endpoint opened earlier and that remains pinned through logical remote CLOSE. Thus even a driver resetting counters on actual native open would leak pre-CREATE activity and report old values on remote reopen. Snapshot counters at each successful logical remote open, without breaking open on unsupported drivers, and encode wrapping unsigned deltas on each GET_STATS. If obtaining a trustworthy baseline fails, do not report absolute counts as since-open data. Add tests for a nonzero baseline, distinct deltas, unsigned wrap, and remote close/reopen baseline reset. Actual hardware success remains unverified.

2. Candidate engines/rdp/src/serial.rs:450–452, 480–496 admits an indefinite wait for every open mapped tty. src/desktop/options.rs:128–130 permits 16 mappings, and engines/rdp/src/devices.rs:1161–1195 allows only 16 ordinary outstanding requests and makes the 17th position available only for CLOSE. Sixteen waits on idle ports (or mixed indefinitely pending reads and waits) fill all 16 credits. The valid SET that should reset the mask and complete an outstanding wait with success and zero is rejected with STATUS_DEVICE_BUSY before serial dispatch. CLOSE still works but destroys the handle. Preserve bounded admission and reserve an escape for a valid serial mask-reset even when ordinary credits are exhausted, without sacrificing the close reserve. A lower wait-only cap does not by itself solve mixed indefinite reads and waits. Add a channel-level saturation/regression test for the real request budget, successful cancellation and credit recovery. [Microsoft WAIT_ON_MASK contract](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntddser/ni-ntddser-ioctl_serial_wait_on_mask), [Microsoft SET_WAIT_MASK contract](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntddser/ni-ntddser-ioctl_serial_set_wait_mask).

The wire operation identifiers, ULONG lengths and field indices match MS-RDPESP and the Linux UAPI. Microsoft specifies INVALID_PARAMETER when no wait events are set or a wait is already pending. Nonzero success consumes the latched event, with later wait requiring a new arrival. Under the documented single-reader queue-sampling constraint, the watermark accounts for bytes read between samples (read count exceeds prior watermark, or residual queue exceeds adjusted watermark), including multiple queued reads. PURGE preserves the already sampled pre-flush arrival and continues to cancel only the matched handle's jobs. I found no order, read-authority, stale-handle, pinned-descriptor, or TTY restoration regression in the scoped diff.

I applied integration.patch to a private copy of MAIN serial.rs and byte-compared it to payload and to the test source. Baseline and payload SHA-256 match the supplied manifest. I inspected the supplied Linux logs (2 expected RED failures, 5 focused GREEN, 74 helper + 10 PCSC GREEN) and Mac ARM component compile log. I did not rerun the suite or open devices. The saturation and stats findings are source proofs.
