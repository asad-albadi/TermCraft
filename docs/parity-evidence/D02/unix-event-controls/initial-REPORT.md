# D02 Unix serial event controls and Linux driver statistics

Integrate only engines/rdp/src/serial.rs. DESIGN.md records the scope. The payload and integration.patch contain the same source with five focused tests. Baseline and candidate hashes are in manifest.json. Private manifests and the fixture binary-name substitution are excluded from the patch.

GET_WAIT_MASK returns one little-endian ULONG. SET_WAIT_MASK takes one ULONG and returns no data. The only supported event is RXCHAR. WAIT_ON_MASK requires read authority, a nonzero enabled mask, and no other outstanding wait on that handle. A successful mask set completes any outstanding wait with zero. Invalid or unsupported sets leave it pending. The worker runs its existing five-millisecond timeout only while a job or wait is pending. Each wait uses the pinned descriptor. A wait can see a byte held in the tty queue, a byte consumed by a protocol read, or a byte observed before a successful input purge. Repeating a wait while the same byte remains queued does not report a second arrival. Close cancels the wait and hangup reports disconnected. No new threads, termios setters, or native handles are introduced.

On Linux, GET_STATS reads TIOCGICOUNT, encoding the six SERIALPERF_STATS counters from the kernel into the 24-byte payload. The Linux PTY rejects that ioctl and the helper returns STATUS_NOT_SUPPORTED. Positive driver statistics are covered by the serialization test using distinct field values and unsigned bit patterns. No physical serial adapter, positive native counter ioctl, original Windows application, or native macOS execution was exercised. Other valid event bits remain unsupported. Queue sampling has the single-reader limitation in DESIGN.md. COMMSTATUS error acknowledgment and hold reasons, and GET_PROPERTIES native capability reporting, remain unsupported.
