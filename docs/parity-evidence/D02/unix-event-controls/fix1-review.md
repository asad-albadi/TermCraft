# D02 Unix serial controls FIX1 re-review

**SPEC ACCEPT for the original two findings. QUALITY CHANGES for one new reserve-admission validation gap.**

1. **ADDRESSED — per-logical-CREATE statistics.** Candidate `engines/rdp/src/serial.rs:238–255` captures a fresh optional baseline when a new logical handle is created against the pinned mapping, and `:738–740` does not substitute absolute counts if the baseline is missing. The Linux native fields are selected as unsigned bit patterns and serialized with wrapping subtraction at `:89–128`. The regression at `:1710–1751` checks initial zeroes for nonzero native counters, distinct deltas for all fields, unsigned wrap, missing baseline even if a later query succeeds, and reset across CLOSE/CREATE. Unsupported native counters do not prevent open. Physical-driver success remains unverified.
2. **ADDRESSED — normal saturated mixed work can reset its wait without dropping the handle.** Candidate `engines/rdp/src/devices.rs:942–953,1172–1183` maintains 16 ordinary credits, permits a serial mask set at pending 16 for mapped Unix serial IDs, and admits CLOSE at pending 17, even with the mask set outstanding. Both queue capacities are bounded at 18 only with mapped Unix serial (otherwise 17). The smartcard branch remains separate at `:1160–1167`. Poll retires one credit per actual completion at `:1057–1064`; a reset emits its own reply and exactly one reply for the original wait via `serial.rs:468–478,510–511`. Worker-side handle and write-authority validation are unchanged at `serial.rs:441,505,706–708`. The new channel regression at `devices_tests.rs:716–820` covers the mixed saturation, bounded admission, same-handle retry, simultaneous room for reset then CLOSE, and reuse of all ordinary credits after reopening. The implementation uses shared pending-count thresholds, not slot ownership. A previously enqueued CLOSE still counts against the threshold for a subsequent reset until a completion is polled. That does not recreate the original all-ordinary saturation deadlock or consume the CLOSE position following a reset.

## New fix-diff finding

**[P3] A reset with unsupported MinorFunction can occupy the mask-reset escape.** At `devices.rs:1179–1181`, the exception checks the device ID, major, and ioctl body but not the request's minor at offset 20. `serial.rs:422–424` rejects every nonzero minor before looking at the port or handle. With the 15 indefinite reads and one WAIT from the new test, an otherwise well-formed SET with minor 1 is queued at pending 16, and the valid SET immediately following it receives DEVICE_BUSY because pending is now 17. The invalid completion releases the credit when polled, so this is not a permanent leak or an authority bypass. However, this structurally invalid packet can take the one escape despite the fix's supported/well-shaped admission rule. Add the minor check in the escape predicate and extend the existing malformed/unmapped saturation test at `devices_tests.rs:738–751` to cover nonzero minor before valid reset. Do not move dynamic handle or access checks into Channel for this fix.
