# P05 · Portable Unix tools

TermCraft provides an app-owned BusyBox environment through **Tools → Portable Unix**. The package workflow previews the selected file and pinned release, then verifies, stages and activates it on a worker thread. It supports install, version change, repair, cancellation, removal and cleanup of retired versions. Tools resolve through the runtime catalog. A terminal holds a shared lease on its installed version until its process is torn down. Reconnect resolves the currently active release. A bounded, cancellable worker verifies the installed tools and starts the PTY, then hands the process and its lease to the tab. The Tools panel caches registry status until refresh or a completed package operation. Child launches set a private tool search path, home and startup configuration. Native Local sessions continue through their existing launch path.

In the package manager, a file lock serializes mutations across app instances. A separate registry lock coordinates active version resolution and retirement. Cleanup snapshots and later commits retired versions in short registry transactions. It checks cancellation between bounded operations and leaves the registry free while it hashes and moves files. The installer copies the compressed input into a private temporary file while hashing, then extracts from that verified copy. The USTAR allowlist accepts regular files at the declared command paths and the license path. It rejects absolute or traversal entry paths, links, special entries and unapproved metadata. Compressed size, expanded size, per-entry size and trailing padding are bounded. Native executable architecture and binary hash are checked before registry activation. Replacement of the registry file is the activation point. Failed or cancelled installations keep the prior registry. Cleanup derives owned command and license paths and hashes from the pinned release. It opens regular files without following links, uses nonblocking opens on Unix, and checks file identity and pinned bytes after moving each candidate to a private quarantine. If an editor changes the entry during cleanup, the moved file remains recoverable under a `.retained-*` directory in the retired version. If possible, cleanup also restores the original name without overwriting its current occupant. Cleanup visits the complete retired-version snapshot (the installer caps retained records at 128), with cancellation between records and during hashing. Older live leases cannot prevent a later closed version from being reclaimed. Cleanup defers versions with live leases and leaves additional and modified files in place. The persistent private home is separate from installed version directories.

## Reproduction

```sh
python packaging/unix-runtime/stage.py --output target/p05-bundles --cache target/p05-cache
cargo test --offline --test package_manager -- --include-ignored
cargo test --offline --lib packages:: -- --include-ignored
cargo test --offline --bin harbor-workspace portable_open_button -- --include-ignored
```

- [RED log](package-manager-red.log) records the missing APIs before implementation.
- [Real Linux workflow](package-manager-green.log) installs upstream 1.31.0 and 1.35.0 bytes. A real PTY from the older release remains live during an update and invokes its own tools after activation. A new shell runs the newly activated `mkdir`, `cp`, `grep` and `sed` with only the portable binary directory in PATH. A restart preserves home. A failed digest check and cancellation after extraction starts leave the older release active. Removal is deferred while a lease lives. Cleanup removes installed files and leaves a changed `cat` and the home file. A separate PTY test verifies child HOME and PATH do not alter the parent. A tampered ownership receipt cannot authorize deletion of extra files. An expected command replaced by a FIFO promptly fails resolution and remains present during removal.
- [Archive checks](archive-tests.log) cover traversal, absolute paths, links, special files, unsupported extended headers, oversized entries and a mismatched ELF architecture. The retirement tests replace a candidate with editor bytes and another with a FIFO between inspection and move, then find the retained copies. A separate test pauses and cancels cleanup while command resolution and a new installation succeed.
- [Cleanup fairness regression](cleanup-fairness-green.log) keeps eight old releases leased across real repairs, retires and closes the ninth, then checks that its files are reclaimed while all eight live releases remain intact. After closing the other leases, cleanup reclaims the remaining eight versions. The [pre-fix run](cleanup-fairness-red.log) failed because the ninth release was starved.
- [Tools panel pointer test](pending-terminal-ui.log) clicks the Portable Unix section and the actual Open Unix terminal button, pauses delivery of the real BusyBox PTY, and verifies another terminal still accepts input and renders a response. Closing the pending tab cancels delivery, reaps the child and releases the package lease.
- [Pinned archive hashes](bundle-hashes.log) cover both Linux releases and the Windows artifact. Windows FRP-6354 is the official Unicode PE x86-64 candidate and imports Windows system DLLs. The corresponding source archive contains the selected build configuration, license and artwork notices.
- [Windows source check](windows-source-check.log) compiles the actual package, environment, input queue and ConPTY backend source for `x86_64-pc-windows-msvc` in a focused dependency harness. The harness also checks the process and lease are transferable between threads and compiles the Windows drive test. Full cross-build stops in the native build toolchain for lack of `lib.exe`. Native Windows installation, drive paths, ConPTY execution and file locking still require Windows validation. The Windows integration fixture checks that the installed shell reads an actual drive-qualified path containing spaces.

## Original format evidence

Read-only fixture downloaded on 2026-11-24 from the official [Mobatek plugin catalog](https://mobaxterm.mobatek.net/plugins.html). The official catalog links the sample as [CygUtils.plugin](https://mobaxterm.mobatek.net/CygUtils.plugin) and gives separate instructions for the MobApt package manager.

The sample has SHA-256 `65c17f095ecbbab4c8015e24aa02bc7de1c098704aec3d8b4b7ec81b28a56602`, size 19,529,086 bytes, and starts with the ZIP local file signature `50 4b 03 04`. Python `zipfile` inspected 1,050 entries, 1,049 with ZIP method 0 and one with method 8. The roots are `bin/`, `etc/`, `lib/`, `usr/` and `CygUtilsLicenses.html`. A bounded `FORMAT_ALONE` LZMA prefix decode of two stored entries revealed a shell script and a PE binary. The original executable and plugin were never launched. Vendor bytes were kept only under the build target directory and are absent from TermCraft artifacts.

This particular sample establishes a ZIP container with some independently LZMA-packed entries. Its filename is `.plugin`. Version-specific `.mxt3` behavior, the MobApt repository format, dependencies, package lifecycle, and the plugin loading protocol remain unresolved. TermCraft's native format is a pinned gzip-compressed USTAR regular-file bundle with compiled-in source, license and command metadata. The current catalog covers BusyBox on Linux x86-64 and the Windows x86-64 candidate. The environment uses ordinary OS permissions and provides no filesystem isolation.
