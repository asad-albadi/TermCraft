# X05 independent candidate review

Reviewed private candidate `target/agent-work/x05/` and its 234-line integration patch against the approved X05 plan and shared parity contracts. Review is source/protocol inspection plus inspection of recorded focused/live logs; no production sources were changed and no live display operation or broad rerun was performed.

## Important finding

**[P2] Drain terminal output while confirming the environment launch.** In candidate `src/ssh/worker.rs:724`, shell startup has already succeeded, but `:728–809` awaits a separate channel's open/X11/exec exchange before the shell is split at `:814` and read at `:931`. The connection sets `channel_buffer_size: 64` at `:442`. The actual dependency implementation (`russh-0.65.4/src/channels/mod.rs:471`) creates a bounded Tokio receiver of that size, and its single client packet dispatcher awaits `chan.send(ChannelMsg::Data { ... })` in `src/client/encrypted.rs:629`. A valid shell startup producing more than 64 output messages before the environment reply therefore blocks that dispatcher on the unread terminal channel, preventing processing of the desktop channel's confirmation. The environment then reports a spurious ten-second launch timeout; the shell only starts draining after timeout/close handling finishes. This is a cross-channel progress bug, not merely expected event-consumer backpressure. Run shell draining concurrently with startup confirmation, preserve the existing bounded output path and cancellation, and retain Connected/startup-macro ordering. Add a focused regression with >64 terminal messages emitted before the desktop request is confirmed, asserting successful launch without timeout and retained terminal output. Existing fixtures emit only one shell-ready line (`tests/support/remote_environment_ssh.rs:160`), so the recorded tests do not exercise this condition.

## Other reviewed behavior

- Legacy serde compatibility is preserved: `Session` defaults the new enum to None, omits None on save (`src/model.rs:214–215`), and the focused legacy test exercises both directions.
- Presets/custom command resolution is explicit and bounded (`src/x11/remote_environment.rs:52–80`). Every SSH command argument is shell quoted (`:43–49`); the custom script is deliberately interpreted remotely by `sh -lc`. The new URI/file tests reject command-bearing launch input. No new inbound command surface is introduced by the patch.
- The desktop uses a separate exec channel (`src/ssh/worker.rs:737–759`) and the existing per-connection forwarder/cookie, so it does not write terminal input or attach to another connection. Incoming X channels still verify the substitute cookie before connecting to the authenticated owned display (`src/ssh/x11.rs:97–125`, `:242–249`).
- Authoritative SSH configuration is still resolved once at worker `:369`; launch consumes `resolved.session` at `:386`. Nonterminal read/gateway purposes leave before the new launch block. Installed SSH rejects a selected desktop explicitly (`src/connection.rs:48–50`). The session editor writes the new enum directly (`src/ui/xserver.rs:223–271`) through its established SSH settings entry point (`src/ui/pages.rs:150`).
- Setup is bounded to ten seconds, failure closes the dedicated channel with a bounded wait, and reports output/state while continuing terminal setup (`src/ssh/worker.rs:762–808`). A JoinSet owns desktop monitoring (`:727`, `:765`); the connection-level cancellation select drops the worker and its lease independently of a full event queue (`src/ssh/mod.rs:270–276`). The existing forwarding lease expires only its own forwarder on drop (`src/x11/forwarding.rs:86–89`).
- Connected follows launch confirmation, which preserves the intended startup macro ordering (`src/ssh/worker.rs:759`, `:810`). This ordering should remain when fixing concurrent terminal draining.

## Evidence and remaining gaps

`unit-final.log` records 5 focused passes and 4 intentionally ignored cases. `live-final.log` records 3 private SSH/owned-X lifecycle passes. The fixture runs actual remote child shells, requests authenticated X forwarding on both channels, maps a test window and checks VIEWABLE, checks exactly one launch and unrelated-session isolation, proves a real shell command after missing-binary failure, and covers cancellation while exec confirmation is pending. These are useful launch/lifecycle results and are not full-desktop validation.

Native Windows/macOS, installed XFCE/MATE/LXQt/GNOME visual and interaction runs, remote display-manager compatibility, and original-product comparison remain pending as already recorded in implementation.md. Timeout/rejection-specific recovery and the startup-output regression above are not directly covered by the current candidate tests. The parent owns integration and the merged whole-suite gate. Do not mark X05 full desktop parity complete from this fixture.
