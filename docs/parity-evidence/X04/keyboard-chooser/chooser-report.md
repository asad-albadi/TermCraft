# X04 owned Linux XDMCP Indirect chooser

The actual remote chooser could display its host menu, accept a target, then lose the selected desktop because the launcher always supplied Xephyr's `-once`. In Xorg 21.1.26 `os/xdmcp.c`, closing the first XDMCP session client terminates with that flag and resets/requeries without it. In xdm 1.1.17 the real Athena chooser sends its choice to xdm and exits. The launcher now uses `-once` only in Direct mode. Indirect keeps the same owned nested server available across the chooser's reset and until the app stops it or the process exits. No changes to the clipboard, authentication, network listeners, keyboard engine, binary payload or readiness protocol.

## Verified

- Frozen application code plus the new fixture saw real xdm use the initial UDP 1177 endpoint, mapped the real chooser, and closed the owned Xephyr after the chooser selected its target. Both Disabled and Bidirectional reproduced the same red lifecycle failure in the ordinary app case. See `evidence/production-red.log` and `evidence/production-clipboard-red.log`.
- On the candidate, both normal cases reproduced the private chooser, selected the real second xdm via UDP 177 forwarding, and observed that xdm's negotiated authenticated 800x600 client render a reference pixel on :177 with the same owned Xephyr PID. The initial manager did not map a login window. Distinct xdm instances and bind ports were observed. The test drives XTest events against the actual pinned chooser after its host row is visibly populated.
- An independently started Direct :178 session and the namespace's pre-existing parent Xwayland display survived the pending chooser close and selected-session close. Both stopped owned sessions removed their PID, X authority file and Unix listener. No host manager, host display, home, clipboard or host-network operation was performed. The chooser wrapper grants `CAP_NET_BIND_SERVICE` only in the private network/user namespace and places HOME in its private temporary mount.
- Bidirectional exchanged actual Unicode text in both directions with an independently authenticated client in the selected manager's session. Disabled uses the existing stock Xephyr path without a clipboard bridge. Earlier Direct startup, exact-port, discovery, auth and clipboard coverage remains separate.
- Final focused library suite passed 40 with 9 isolated/manual cases skipped by the ordinary lib invocation. Both new ignored real cases then ran separately and passed. Format check and scoped patch replay passed. See `evidence/final-*.log` and `verify.sh`.

## Scope limits

The private fixture opens xdm's real setup client to verify negotiated X11 authorization and pixels. It does not claim OS/PAM credential login, a production remote desktop environment, IPv6, original-product parity or Windows/macOS evidence. The standard chooser query and forward targets use UDP 177 per pinned xdm upstream even though the initially queried manager honors the app's custom port. App cancellation is tested. Final remote logout/relogin semantics and choosing the initial manager itself were not separately tested. Source review found that Xorg can use the first authorized client after MANAGE for XDMCP session bookkeeping, so clipboard reconnect ordering across an atypically delayed manager reset remains unresolved outside the tested normal flow. No synthetic reset-order fixture ran, no broader compatibility claim is made, and no engine change is staged.

From the work directory, run `./verify.sh` with its extracted `verified-fixture` and workspace-package paths intact. To recreate the fixture into a new directory, run `source/tests/support/prepare_xdmcp_chooser_fixture.sh ../x04/source-packages archives verified-fixture-new`. The extra x86_64 Arch libXaw archive came from the pkgbuild.com Arch mirror and matched the local Arch package database SHA-256. The cached x86_64_v3 CachyOS libXmu package matched its corresponding local package database SHA-256. These are private test inputs only. The remaining native runtime libraries are the existing private X11 test host's Xlib, Xt, XTest, Xinerama and loader dependencies.
