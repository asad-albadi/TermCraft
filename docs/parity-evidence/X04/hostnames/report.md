## What changed

- The workspace ends XDMCP editor state on Cancel, window X, accepted Save or Connect, protocol exit, and each explicit editor opening/replacement, including opening the same saved profile over itself. A validation failure that retains the form keeps the live XDMCP editor. End-of-editor advances its generation, discards rows and the transient binding, and drops the pending resolver/discovery handles without joining either worker.
- A hostname resolver completion is polled for application only after the current frame is known to retain its editor. In particular, a ready completion on the X/Cancel or successful Save/Connect frame cannot initiate UDP discovery from paint. Regular painting by itself still initiates neither resolution nor discovery.
- New explicit Resolve/Discover actions clear previous resolved and discovered rows before attempting the new request, including when the start fails immediately. Pending requests no longer share a separate Discover intent flag. A deliberate, exact-request selection remains separate from old rows and is checked against a successful fresh answer. Connect still resolves independently and rejects a missing selection preference before engine startup, with no stale-address fallback.
- Unchanged resolver constraints include a global two-call permit retained through OS resolver return, a two-second caller resolution phase off the UI, no waiting for cancelled OS lookups, exact host/port/mode/generation checks, IPv4-only candidates, and existing listener consent and X11 access controls. The application buffers at most 33 iterator items as a cutoff sentinel and admits at most 32 into candidate processing. The standard library tuple ToSocketAddrs can already have eagerly allocated native results before the cutoff, so this is not a limit on total OS or standard-library answer materialization.
