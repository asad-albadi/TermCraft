# X04 Linux bidirectional text clipboard candidate

Status: a private scoped addition, not full X04 or native/original parity. Package version 0.1.934; ordinary application binary `termcraft-xdmcp-clipboard934`. Source snapshot includes Cargo inputs, vendor/runtime/engines, assets/data, tests, FEATURE_PARITY.md and other package resources. No MAIN files were edited.

## Result and boundary

Linux opt-in Bidirectional now bridges UTF-8 CLIPBOARD text between an explicitly selected local parent X11 display and the owned nested Xephyr display. The selected parent can be Xwayland; this does not establish Wayland compositor clipboard sharing. Disabled returns before constructing any bridge, opening a parent clipboard connection or allocating selection windows. It ignores even malformed unused parent clipboard settings. Windows/macOS native engines remain unavailable; their UI offers Disabled and does not advertise a qualified bridge. No PRIMARY, binary formats, implicit DISPLAY clipboard choice, environment mutation, authority mutation, `-ac`, input injection or other process termination was added. Xephyr still uses its existing host DISPLAY only to create its nested window.

Per-lease workers own their authenticated connections, windows, retained child pidfd, transfer state and cleanup. The already PID-verified readiness UNIX descriptor is authenticated using the private client cookie. The explicit parent socket uses local peer PID/UID identity and bounded regular-file Xauthority parsing; an explicit/default existing authority must contain a matching MIT cookie. No server access-control bypass is introduced. Errors terminate the lease with a clipboard-specific error rather than silently dropping the opted-in capability. Worker cancellation/drop removes only that client's windows and is joined before the owned server stops; GUI drop remains the existing cancellation flag on ManagedXdmcp.

XFixes owner events detect same-owner content changes when an ICCCM owner reacquires its selection. Fresh requestor windows and source timestamps separate epochs. TARGETS must offer UTF8_STRING; only valid UTF-8 without NUL, up to one MiB, is accepted. INCR is supported for incoming/outgoing UTF8 text, including multibyte characters split across chunks. The final byte count must meet the announcement's lower bound; prematurely terminated transfers are rejected. Unsupported targets, malformed/oversized text, stalled owners, stale epochs and disappearing requestors do not replace valid destination text. Transfers have a two-second total deadline; outgoing state is capped at four requestors and one MiB aggregate snapshots. Event work is capped per tick. Text/cache/property buffers are zeroized.

Clear propagates only if this lease still owns the destination. ROOT clarified that Bidirectional mirrors actual parent clipboard changes, including another enabled lease's publication. A -> parent -> B propagates once; the bridge suppresses its own selection-window notifications and invalidates stale pending epochs/publications to prevent bounce. Clear follows the same actual-parent rule. A concurrent Disabled C stays untouched. If both servers change in one observation round, the nested external event wins. The earlier private prototype's process registry/foreign-owner exclusion was removed before handoff; the generic Bidirectional label does not silently omit another enabled lease's parent changes.

## Real display-manager lifecycle

The initial managed run correctly failed: upstream xdm SecureDisplay/pseudoReset kills clients with windows. Normal operation retains both connections, but a dropped nested endpoint is reconnected with a fresh peer-PID check before authentication and checks against a retained pidfd before/after connecting. The unchanged private client cookie works after the real manager has installed negotiated authorization; production never reads the manager's cookie. The parent connection remains retained. Recovery permits at most three nested resets per thirty seconds. It clears only this lease's own parent publication, discards previous nested text, and resamples current external parent state, avoiding carrying old desktop text across a reset/login boundary.

The source-grounded design was written before implementation in the sibling artifact `design.md`. Primary references: [X.Org ICCCM chapter 2](https://xorg.freedesktop.org/releases/current/doc/xorg-docs/icccm/icccm.html), local x11rb 0.13.2 generated XFixes/protocol/connection source, pinned xorg-server 21.1.26 authorization/XDMCP source, and xdm 1.1.17 `xdm/reset.c`, `session.c`. Existing VNC code informed bounded transport conventions and was not edited.

## Limits

This is text-only ICCCM/XFixes qualification on the pinned Linux x86_64 Xephyr candidate and controlled private servers/managers. Owners that silently mutate without reacquiring, UTF8 targets without TARGETS, very slow transfers, unsupported/binary formats, runtime qualification of multiple application processes, native Windows/macOS, compositor-level Wayland clipboard, full chooser/keyboard/RandR/native monitor behavior and original MobaXterm runtime parity are not established. The bounded reset retry limit is deliberate; repeated manager resets can end the lease with an explicit error. Existing XDMCP listener/authentication/network limitations in the main X04 record still apply.
