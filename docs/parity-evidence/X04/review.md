## Important — reject nonregular engine files before blocking open/read

Private `src/x11/xdmcp_engine.rs:194–205` loads the configured installed engine with `File::open`, followed by `take(...).read_to_end`. Neither operation rejects a FIFO/device or a symlink targeting one. A FIFO at `x11/linux-x86_64/Xephyr` blocks in open while waiting for a writer; a writer that remains open can instead block read. This occurs before the eight-second startup deadline at line 291. Dropping/cancelling `ManagedXdmcp` only sets an atomic flag, which the blocked worker cannot check, so this startup worker never finishes. This requires a malformed/replaced local payload; it is not a remote peer attack or an executable pin bypass.

Fix scope: open the engine nonblocking, validate the opened descriptor is a regular file before reading it, retain the current byte/hash bounds and sealed execution. Reject symlinks explicitly if adopting the existing release source policy; a path-only metadata check is insufficient against replacement between check and open. Add bounded regressions for FIFO, wrong-type and symlink inputs, plus cancellation/worker completion during loading, without opening any X display. Start the end-to-end startup deadline before payload loading and check actual cancellation/deadline between bounded read/hash/copy chunks. Ordinary pinned engine staging/startup must continue to work.

Verification: a disposable local FIFO and isolated subprocess using the same blocking open/read sequence remained blocked for the 200 ms observation period; the reviewer explicitly killed and reaped that subprocess. Production source establishes that its only startup deadline/cancellation checks cannot run during this blocking call. No host X/display/network access was used for this reproduction.
