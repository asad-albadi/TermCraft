## Implemented candidate

- Persisted `Session.xdmcp_options` uses serde defaults and omits default values; legacy sessions remain readable. Query mode, selected numeric endpoint, custom port, display, fullscreen/monitor, inherited keyboard and clipboard policy are structured. The workspace routes XDMCP to a dedicated worker and owned per-session lease, refuses automatic installed-client fallback, exposes cancellation/disconnect and never labels X server readiness as a connected remote desktop.
- New `Discovery` owns one fresh UDP socket per operation. Direct QUERY=2 and INDIRECT_QUERY=3 use exactly the selected address/port. BROADCAST_QUERY=1 requires explicit local IPv4 interface and /16–/30 network selection and an explicit Discover click; the destination is derived from that choice. No interface scanning or automatic broadcast is performed. Three query packets maximum, 600 ms deadline, 30 ms cancellation poll, 128 received packets, 32 unique endpoints and a 1,024-byte packet bound. Headers, lengths, version/opcode and capped fields are validated. Unicast responses must match the queried source IP AND port; broadcast replies must match selected subnet and port. Strings containing controls/invalid UTF-8 are rejected. Duplicates are folded by source endpoint. QUERY has no transaction identifier; fresh ephemeral socket plus these checks provide correlation, not authentication.
- The Linux adapter uses a separately pinned owned Xephyr 21.1.26-1 image, read with a 16 MiB bound, SHA-256 checked and executed from a write/grow/shrink sealed memfd. Xwayland's existing build explicitly disables XDMCP, so it is never given these arguments. A random high display or explicit nonconflicting display is used; pre-existing sockets/locks are refused and the engine retains exclusive-lock/complete-bind checks. Readiness verifies the exact selected display and Unix socket peer PID against the unreaped owned child. A bounded /proc TCP/TCP6 table and child-fd inode check additionally requires every listening socket on 6000+display to belong to that child; absent, foreign or unverifiable listeners abort and drop only the owned engine. Stock Xephyr cannot safely inherit a reserved TCP socket: there remains a pre-bind race window before this post-bind ownership check. Removing that window requires a patched upstream engine accepting reserved TCP descriptors; cookie authorization does not authenticate a spoofed server to remote clients. Credentials are random, private and per-session; `-ac` is never passed. Child PID ownership and existing `OwnedProcess` cleanup are reused. Startup has an eight-second bound; ongoing diagnostics are drained with a memory bound. Process stop and filesystem cleanup occur on the worker.
- TCP listening is denied by default. The user must explicitly permit **unencrypted XDMCP/X11 plus the session's all-interface inbound TCP listener** before the worker can start. This is the upstream Xephyr listener's actual scope. `-from` advertises a selected local non-loopback IPv4 address; it does NOT bind/restrict TCP. Xephyr excludes loopback from the advertised Request address list, so a loopback advertised address is rejected before launch. Discovery can still query a controlled loopback manager.
- Monitor selection passes `-output NAME` without `-screen` or `-fullscreen`: upstream `hostx_init` checks `use_fullscreen` first and would otherwise ignore the output; `-output` itself creates the selected screen and applies fullscreen geometry. Passing both `-screen` and `-output` creates two screens and crashed the real candidate in the private test; the production adapter now selects exactly one screen source. Ordinary fullscreen without monitor uses `-fullscreen`. Invalid names are rejected syntactically and unavailable/disconnected outputs fail in the actual engine. Window size is explicit for windowed mode. Xephyr's `EphyrKeyboardInit` overwrites Kdrive layout with the host keymap, so custom layouts fail specifically rather than pretending `-xkb-layout` is applied. The UI states host keyboard inheritance and can clear unsupported imported selections.
- Clipboard Disabled starts no host bridge. Bidirectional is an explicit capability error and disabled UI choice, never a no-op. Existing normal X server options, X03 probes and SSH/X02 configuration are unchanged. No active RandR capability probe is run against an ongoing XDMCP session; this candidate is not claimed X03-qualified.

## Real controlled interoperability

`tests/support/run_xdmcp_isolated.sh` is an opt-in extension of the existing private bwrap/Cage harness. It first creates separate user/network/PID namespaces and checks namespace identity before changing any interface. CAP_NET_ADMIN is confined to that new user/network namespace. A private TEST-NET veth (192.0.2.1/30) supplies the non-loopback address Xephyr requires; no host/LAN broadcast occurs. Existing host socket-directory identity and pre-existing private Cage Xwayland PID checks remain. The ordinary Xserver harness is not modified.

The pinned xdm 1.1.17 fixture has empty Xservers and its own config/access/auth/PID/error files. Its allowlist names only 127.0.0.1 and private 192.0.2.1. It runs foreground, without PAM login, with authorization enabled and MIT-MAGIC-COOKIE-1. Debug level zero avoids cookie dumps. A negotiated-authority setup client maps an actual green window, checks its reference pixel and reports dimensions without recording credentials. The test discovers xdm on UDP1177, starts selected :177 at800x600, rejects a wrong-cookie client, creates a second session on :178 with a live private RandR monitor/fullscreen selection, closes the first, verifies the second and Cage display survive, then verifies both child PIDs and authority files are removed. The fixture display manager and its descendants are also owned and terminated.

The initial actual xdm test was RED: no advertised address on the empty netns. A subsequent controlled run correctly rejected a non-allowlisted TEST-NET source. The deterministic socket-saturation regression initially used the OS default backlog; the test was corrected to explicitly set backlog 1 without loosening its production deadline. The final fixture also needed pinned libXpm to load its actual greeter. These failures were not relabeled as passing mocks; their root causes and constrained fixture fixes led to the real run.

## Scoped review fix — payload loading cancellation (2026-11-25)

The independent review in MAIN `docs/parity-evidence/X04/review.md` found that the original `File::open(...).read_to_end(...)` could block on a FIFO before the startup deadline existed. That Important finding is addressed by `src/x11/xdmcp_payload.rs`, called directly by the existing owned engine launcher. The loader uses `O_NONBLOCK | O_NOFOLLOW | O_CLOEXEC`, then checks the **opened descriptor** is a regular file and its declared size is at most16MiB. FIFOs, directories and final-component symlinks are rejected before reading. A concurrent content change cannot bypass the fixed pin: the exact64KiB chunks copied to the private memfd are incrementally hashed, with total byte growth bounded as well. The original exact SHA256 and write/grow/shrink seals are retained.

The single eight-second startup deadline now starts before payload loading and is reused through child readiness; it is not reset after loading. Cancellation and deadline are checked before/after open/metadata, each bounded read, each bounded hash update, each copy write, hash finalization and sealing, and immediately before spawn. These checks bound cooperative loading work and eliminate FIFO/device blocking; they do not claim to preempt arbitrary kernel/filesystem stalls during a syscall. Auth files, packaging staging, listener ownership, socket checks and per-session cleanup policy are unchanged.

RED: `evidence/red-payload-review.log` records the absent loader API before implementation. GREEN: `evidence/green-payload-review.log` records the initial three focused regressions; the final `evidence/final-review-fix-lib.log` has **16 passed, zero failed, one explicitly ignored live test**. Deterministic tests use disposable FIFO/directory/symlinks/sparse oversized files without any X display, a real-file reader that triggers the same cancellation flag during loading and proves worker completion before any copy, a deadline crossed during a real file read, and multi-chunk real-file digest/copy checks including wrong-pin rejection. Invalid-type/cancellation/deadline worker completion is bounded by a500ms test observation budget.

Because the loader changes the ordinary runtime image path, the real private xdm case was rerun: `evidence/final-review-fix-real-xdm.log` is **one passed, zero failed**. It preserves the pinned Xephyr payload, custom UDP1177, selected display and actual monitor geometry/green pixels, wrong-cookie rejection, second-session independence, TCP inode ownership and owned cleanup while the private Cage display survives. `evidence/review-fix-fmt.log` is empty/success. No broad private GUI suite was run for this correction. All review-fix commands completed before handoff. X04 remains partial and the global40/60 checkpoint is unchanged; ROOT must perform fresh scoped review before integration.
