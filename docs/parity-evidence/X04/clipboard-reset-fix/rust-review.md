## Specification and quality assessment

- The captured genuine f024 traced RED remains valid baseline failure evidence: EOF at Endpoint GetSelectionOwner escaped initialization; the other case hit the existing 3/30 reset protection and the owning app then stopped its engine. The sealed `../current-packaged-xdmcp/reliability-boundary/owner-handoff.md` was read without exposing raw authorization payloads. Native lifecycle causality is supported separately by the accepted native review; the old handoff's original hypothesis is not itself treated as proof.
- `recover_endpoint` encloses authenticated stream setup plus the complete `Endpoint::new` in one retry operation. All constructor request/reply, create-window and checked selection-conversion paths preserve transport error kinds, including `begin(owner)` when an owner already exists. Only UnexpectedEof, ConnectionReset, BrokenPipe and ConnectionAborted are retried. Failed partial connections/endpoints are dropped through Rust ownership before the next loop. There is no new arbitrary sleep, count relaxation, or renewed initializer budget.
- Typed error mapping was checked against the locally installed x11rb 0.13 error definitions. Direct ConnectionError and wrappers ReplyError / ReplyOrIdError expose only IoError kinds; ConnectError IoError and truncated handshake Incomplete map appropriately. SetupFailed / SetupAuthenticate, parse/decode errors, X11Error replies, unsupported extensions, invalid screens and exhausted IDs map to Other and fail the retry match. Interrupted and TimedOut also fail it. No authentication or protocol rejection is converted to a retryable disconnect by string matching.
- Each attempt first checks the retained owned pidfd, obtains a fresh local socket, reads fresh SO_PEERCRED and requires the exact child PID, then checks the same pidfd again before cookie transmission. The identity is never reopened from a recycled PID. Wrong identity is fatal and receives no cookie. Transport connect and every subsequent read/write/poll enforce stop/deadline; cancellation or expiry cannot start authentication. Failures before authentication drop their owned stream. There is no remote transport or foreign-parent fallback.
- All initializer attempts share the `now + 2s` deadline for the current recovery episode, including any time already spent clearing the parent. The parent request budget remains min(250ms, remaining epoch), with no per-attempt renewal. `run` still allows only three recovery episodes in 30 seconds. The helper's internal attempts do not spend new episode slots or bypass the episode limit. The existing behavior of initiating recovery for nested tick/publish failures is unchanged; the new helper does not suppress fatal bootstrap errors.
- Parent clearing happens before reconnection; it removes ownership only when the bridge owns CLIPBOARD. After recovery the code resamples the current external parent owner, instead of replaying old nested history across login/reset. Cancellation/join, owned process/authority cleanup, bounded transfer state and zeroizing clipboard/cookie ownership remain in place. The additional retries use the existing authenticated connection path, rather than introducing persistent resources or another cookie store. Existing x11rb temporary handshake-buffer behavior is unchanged.
- Caller `session_ready` remains bidirectional clipboard OR explicit keyboard. The new `-termcraft-internal-clipboard-parent` flag is supplied only for bidirectional clipboard and follows `-termcraft-session-ready`, matching the accepted C parser contract. Keyboard-only uses readiness without the new flag; stock host keyboard / Disabled uses the existing stock asset. The added actual-caller test reads the owned child's command line and checks the flag against clipboard policy.
- `load_ready_engine` embeds the payload binary digest while stock retains its independent fixed digest. Manifest, cumulative native patch, compressed payload, decompressed native ELF and embedded 32-byte digest agree on production `81315f3d245b241a7fd8fd6ecf30a192edde0028bc43d5d0ba3d17b36889c92e`. Diagnostic native ec3733 and intermediate app 982 are not substituted for this source or executable.
