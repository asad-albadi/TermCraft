3. **Retained-evidence verification is narrower than fresh native execution.** `verify.py` checks pinned executable bytes, declared backend/environment, six reports with exactly 14 observations, case counts, terminal expected bytes, scale, screenshot presence and packaged engine identifiers. It does not independently recompute every theme/clipboard/VNC assertion, verify all runner/source hashes, or re-execute native inputs. Those assertions occur in `matrix.py`; the evidence/source manifests and raw artifacts supply the reviewable provenance. Keep the three Rust validators explicitly described as validators, with zero contribution to 84 native observations. Do not interpret a later `--verify` PASS alone as a fresh matrix or a source-change qualification. This review independently checked the retained raw outcomes below.

## ADDRESSED — compatibility boundary

Static comparison supports default inactive-game compatibility, with a specific limit. `PlayState::default` sets `launcher=false`, `suspended=false`, `session=None` and `close_owner=None`. In this state, `games_frame` returns false before consuming events, painting a game, requesting repaint, changing focus or mutating input. Both current root guards and the detached guard therefore pass through to the existing terminal/desktop paths. The new screensaver early branch is conditional on `play.is_open()` and is inactive by default. The frozen snapshot already contains the remaining idle-screen behavior. Appearance application remains before the root guards. This is source-based compatibility evidence, not a native replay result.

The historical bounded .706 checkpoint can be retained after findings 1–2 are corrected and its snapshot limitation stays explicit. If the checkpoint is intended to qualify **current parent code**, a focused current-source native replay is needed first: keep all game hooks present, assert default inactive game/idle state, and exercise X11 and no-DISPLAY Wayland at fractional scale through idle System theme transition/stable overrides, real-peer Unicode/multiline confirmation and PTY delivery, root/detached SGR input and detached VNC coordinates. Record fresh source/executable hashes. A broad six-session repetition is not required merely to characterize the localized default-state guards. Active game, game suspension/close-owner and game/screensaver lifecycle behavior remain the separate open B06 native task; this V06 review does not close them. The root's current-source Rust suite is complementary and cannot replace these native observations.
