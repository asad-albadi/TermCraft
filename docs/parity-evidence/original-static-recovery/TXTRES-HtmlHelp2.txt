<SousParagraphe>Passwordless ssh connection
<br />
<br />
<br />
You can connect to an SSH server without supplying any password: this
is useful if you want to run shell scripts that are not interactive.
This can be done in 2 steps:<br />
<br />
<SousSousParagraphe>On client side
<br />
You will have to
generate a public rsa key on the client. This can be done by launching the "MobaKeyGen" tool (from the "Tools" menu) or by typing
<div class="term">ssh-keygen -t rsa -N '' -q -f ~/.ssh/id_rsa</div>
<br />
<br />
<SousSousParagraphe>On server side
<br />
Copy the file that has
been generated on the client (".ssh/id_rsa.pub")
to the ~/.ssh/ directory of the server and rename it to
"authorized_keys".
<div class="term">scp .ssh/id_rsa.pub user1@server1:.ssh/authorized_keys</div>
<br />
<br />
<br />
<br />
<br />
<SousParagraphe>Passwordless rsh connection
<br />
<br />
<br />
You can connect to an RSH server without supplying any password: this
is useful if you want to run shell scripts that are not interactive.
This can be done in 1 step:<br />
<br />
<SousSousParagraphe>Using /etc/hosts.equiv
<br />
Edit the
/etc/hosts.equiv file on server side: you can specify in this
file the authorized users that will be able to connect to the server
without supplying any password. The file syntax is:
<div class="term">&lt;computer_name&gt; &lt;user_name&gt;</div>
<br />
<br />
<SousSousParagraphe>Using ~/.rhosts
<br />
Edit the ~/.rhosts file
on server side: you can specify in this file
the authorized users that will be able to connect to the server using
the current account without supplying any password. The file syntax is:
<div class="term">&lt;computer_name&gt; &lt;user_name&gt;</div>

<SousParagraphe>Startup commands
<br />
<br />
<br />
You can add some startup parameters for MobaXterm in 2 ways:
<br />
<SousSousParagraphe>Using command-line parameters
<br />
You can edit a shell
script (be careful, it has to be in Unix and not
Dos format) and run it at MobaXterm startup. You just have to launch
MobaXterm with the following command-line:
<div class="term">MobaXterm.exe &lt;script_file&gt;</div>
<br />
MobaXterm also uses some internal command-line parameters that can be used by advanced users in order to integrate MobaXterm in their own environment:<br />
<div class="term">MobaXterm.exe -exec &quot;&lt;Command&gt;&quot;</div>
This command can be used to start a new instance of MobaXterm and immediately execute a given MobaXterm command<br />
<br />
<div class="term">MobaXterm.exe -newtab [&quot;&lt;Command&gt;&quot;]</div>
This command can be used to start a new tab inside a running instance of MobaXterm (or start a new instance of MobaXterm if no other instance is running) and immediately execute a given MobaXterm command<br />
<br />
<div class="term">MobaXterm.exe -bookmark &quot;&lt;Bookmark_name&gt;&quot;</div>
This command can be used to start a bookmark by specifying its name. (Note: this only work for 1st level bookmarks: bookmarks from subfolders can not be invoked by this command)<br />
<br />
<div class="term">MobaXterm.exe -runmacro &quot;&lt;Macro_name&gt;&quot;</div>
This command can be used to start a macro by specifying its name.<br />
<br />
<div class="term">MobaXterm.exe -openfolder &quot;&lt;Folder_name&gt;&quot;</div>
This command can be used to start MobaXterm in the specified folder<br />
<br />
<div class="term">MobaXterm.exe -hideterm</div>
This command can be used to start MobaXterm that is immediately minimized into the system tray<br />
<br />
<div class="term">MobaXterm.exe -exitwhendone</div>
This command can be used to exit MobaXterm when the given action is finished. This parameter should be combined with -bookmark or -exec<br />
<br />
<div class="term">MobaXterm.exe -i &quot;&lt;Ini_file_path&gt;&quot;</div>
This command can be used to specify a path for MobaXterm configuration file (MobaXterm.ini)<br />
<br />
<div class="term">MobaXterm.exe -log</div>
This command can be used to write down some debug information in a log file<br />
<br />
<div class="term">MobaXterm.exe -installshellext</div>
This command can be used to install the right-click context menu in Windows explorer<br />
<br />
<div class="term">MobaXterm.exe -installprotohandler</div>
This command can be used to install the URL protocol handler, in order for MobaXterm to be able to execute sessions from HTML pages<br />
<br />
<div class="term">MobaXterm.exe -config</div>
This command can be used to start MobaXterm configuration window<br />
<br />
<div class="term">MobaXterm.exe -noX</div>
This command can be used to disable X server for the given MobaXterm instance<br />
<br />
<div class="term">MobaXterm.exe -dpi 120</div>
This command can be used to scale MobaXterm interface if the fonts are too small. You can try the following values: 120 (x1.25), 144 (x1.50) or 192 (x2.00)<br />

<SousParagraphe>General
<br />
<br />
<br />
<SousSousParagraphe>What is the purpose of MobaXterm?
<br />
MobaXterm is an enhanced terminal for Windows with an X11 server, many network tools for remote computing and network commands packaged into a single portable exe file. MobaXterm has been designed to suit the needs of computer users, sysadmins, developers and webmasters by providing:<br />
- a multitab terminal with embedded Unix commands (ls, cd, cat, sed, grep, awk, rsync, wget, ...)<br />
- an embedded X11 server for easily exporting your Unix/Linux display<br />
- a session manager with many network utilities: SSH, RDP, SFTP, FTP, Telnet, Rlogin and XDMCP<br />
- some basic network daemons (TFTP, FTP, HTTP, ...)<br />
- a graphical SSH tunnels builder<br />
<br />
<br />
<br />
<br />
<SousSousParagraphe>What are the main advantages of using MobaXterm over other SSH/SFTP/FTP/RDP/VNC/X11 solutions in Windows?
<br />
MobaXterm has many advantages over its competitors:<br />
- a full All-In-One solution: it features an X11 server, a terminal with embedded Unix/Linux commands and a complete collection of network tools (SSH, SFTP, telnet, rlogin, RDP, VNC, XDMCP, FTP and Serial console)<br />
- a portable solution without the need to install and without the need of administrator privileges: MobaXterm is a single executable self-contained file which does not need to be installed or run with administrator privileges<br />
- no complex settings: there is no need to set up your environment or to tune settings: MobaXterm default parameters have been chosen in order for it to be immediately usable<br />
- some unique features like the remote sessions with saved passwords or the SSH-browser: when you connect to a remote server through SSH, a graphical remote file browser will automatically be displayed allowing you to transfer files or to edit them directly using the integrated text editor &quot;MobaTextEditor&quot;<br />
- a robust terminal based on PuTTY with clean fonts, tabs, keywords coloration, split modes (2 or 4 terminals side by side), Multi-execution (write once, execute everywhere), copy/paste, save/print text and much more<br />
- a non-intrusive program: MobaXterm does not connect to the Internet or write entries into your Windows registry without asking before. It does not automatically check for updates. There is no time limit for using it.<br />
<br />
<br />
<br />
<br />
<SousSousParagraphe>Does MobaXterm perform unwanted internet connections?
<br />
No, MobaXterm has been designed to just perform the connections you request: no background internet connection is done without your consent. Even the update mechanism is manual: MobaXterm will not search for updates if you do not click on the "Check for updates" menu entry.<br />

<SousParagraphe>X11 server
<br />
<br />

<SousSousParagraphe>What is X11? Why would I need an X server?
<br />
The X server (a.k.a. X11) is something very important in a Unix/Linux environment: it is the graphical layer on which all graphical applications are based.<br />
As X11 is a network protocol, applications that can display their graphical interface on a Linux/Unix desktop can also display it through the network on another computer as well. This 2nd computer only needs to run an X11 server to display them.<br />
MobaXterm includes an X11 server, based on "X.Org", that allows you to display remote graphical Linux/Unix applications on your local Windows computer with great speed and performances.<br />
Example: On your remote Unix/Linux computer, you just have to perform the following command:<br />
<div class="term">DISPLAY=MY_WINDOWS_HOST_RUNNING_MOBAXTERM:0.0  xclock</div>
...and you will see the "xclock" interface on your Windows desktop<br />
<div class="info">By default, MobaXterm activates X11-forwarding for the servers that support it. There is no need to set your DISPLAY, just start your SSH connection and launch a graphical application on your server, then the application will appear on your local Windows desktop. This is more secure than forwarding the display, because the network communication will be tunneled through the encrypted SSH connection.</div>
<br />
<br />
<br />
<br />
<SousSousParagraphe>What does X11-Forwarding means?
<br />
X11-Forwarding is a mechanism that allows the X11 protocol to be routed through an existing SSH channel. The main advantages of this solution are:<br />
- X11 protocol will be encrypted<br />
- X11 protocol can be compressed<br />
- There is no need to set up a new communication channel (and to open communication ports in your firewall) for X11: the network packets go through the already existing SSH connection<br />
<div class="info">By default, MobaXterm activates X11-forwarding for the servers that support it. There is no need to set your DISPLAY, just start your SSH connection and launch a graphical application on your server, then the application will appear on your local Windows desktop. This is more secure than forwarding the display, because the network communication will be tunneled through the encrypted SSH connection.</div>
<br />
<br />
<br />
<br />
<SousSousParagraphe>How does X11-Forwarding work?
<br />
With MobaXterm, it is really easy to use X11-Forwarding: just connect to your server and keep the "X11-Forwarding" setting checked in your SSH session. Then, from the remote server prompt, run "xclock". You will see the "xclock" interface which has been transfered through SSH on your Windows desktop.<br />
<br />
<br />
<br />
<br />
<SousSousParagraphe>Why is my remote DISPLAY variable configured to "localhost:10.0"?
<br />
If you check the "DISPLAY" environment variable on your remote server, you will notice that it is set to something like "DISPLAY=localhost:10.0". This is the standard behaviour for X11-Forwarding: it means that any program will use a local virtual display (:10.0) which is created by SSH and which will be automatically forwarded trhough the SSH connection to MobaXterm display.<br /> 
<br />

<SousSousParagraphe>I want to change MobaXterm X server DISPLAY address to my second network adapter (or my VPN adapter). How can I do this?
<br />
By default, MobaXterm Xserver listens on all your network adapters.<br />
The banner message will say that your DISPLAY environment is set to "&lt;some_ip_address&gt;:0.0", but this is an informational message only: it is printed here in order to help users set their "DISPLAY" environment variable when connected to a remote server. However, the embedded X11 server listens on all network interfaces, not only the one which is written in. It does not matter which IP address you see in the "DISPLAY" variable: as MobaXterm X server listens on all your network interfaces, it also listens on the 2nd, 3rd, (...) network interfaces.
For instance, if your computer has 2 network adapters (192.168.0.10 and  10.10.10.36): MobaXterm says your DISPLAY is set to "192.168.0.10:0.0". However the X server really listens on "127.0.0.1" (localhost), "192.168.0.10:0.0" (1st adapter) and "10.10.10.36:0.0" (2nd adapter).<br />
<br />
<br />
<br />
<br />
<SousSousParagraphe>How can I secure the X11 server?
<br />
By default, MobaXterm Xserver listens on all your network adapters, but it will prompt you for each incoming connections that are not local or not issued by X11-forwarding mechanism. You can then choose to accept or reject these connections.<br />
If you are only using X11-forwaring and you want to prevent the X server for listening for incoming connections from the network, you can go to MobaXterm global settings and choose "Disabled" in the "X11 remote access" field.<br />
For Professional users, this setting can be forced into the "Customizer" program so that it will then be impossible for users to activate it.<br />

<SousSousParagraphe>I have an issue with an X11 remote program (Java/X11/Motif) which does not accept keyboard input: every time I press a keyboard key, nothing is written on the text field
<br />

Restart your remote program and it should take keyboard input correctly.<br />
If you want to use the standard "multiwindow" (transparent) X11 server and occasionally use the windowed X11 server with the window manager, you can go to MobaXterm "Settings" window --&gt; "X11" tab --&gt; select "Multiwindow mode" setting in the combo box and apply, then open the "tools" menu and select either "X11 tab with Dwm" or "X11 window with Fvwm2".<br />

<SousSousParagraphe>How can I display a full remote desktop from a Unix/Linux server in MobaXterm (Gnome, KDE, FVWM, Openbox, Fluxbox, IceWM, XFCE, Blackbox, DWM, Enlightenment, LXDE, ...)?

<SousSousParagraphe>What is SSH?
<br />
MobaXterm includes an SSH client (with SFTP and SCP) which allows secure encrypted connections to be set up through the network. The SSH client embedded in MobaXterm is based on the efficient and secure SSH client <a href="https://www.chiark.greenend.org.uk/~sgtatham/putty">PuTTY</a> by Simon Tatham.<br />

<SousSousParagraphe>How can I use SSH keys for authentication?
<br />
On client side, you have to generate a public rsa key:<br />
<div class="term">ssh-keygen -t rsa -N '' -q -f ~/.ssh/id_rsa</div>
Note: You can also use the graphical SSH keys manager "MobaKeyGen" (from the "Tools" menu).<br />
Then copy the file that has been generated on the client (".ssh/id_rsa.pub") to the ~/.ssh/ directory of the server and rename it to "authorized_keys":<br />
<div class="term">scp .ssh/id_rsa.pub user1@server1:.ssh/authorized_keys</div>
If the ".ssh/authorized_keys" file already exists, just append your own public key to the file:<br />
<div class="term">cat .ssh/id_rsa.pub user1@server1:/tmp/tmpkey &amp;&amp; ssh user1@server1 "cat /tmp/tmpkey >> ~/.ssh/authorized_keys &amp;&amp; rm /tmp/tmpkey"</div>
Of course, you will have to set a persistent home directory if you want your generated keys to persist through MobaXterm restarts. A persistent home directory can be set in "Settings" --&gt; "Configuration" --&gt; "General" tab.<br />

<SousSousParagraphe>What is the purpose of the "tunneling" tool (also known as "Port forwarding")?
<br />
The Tunneling tool embedded inside MobaXterm ("MobaSSHTunnel) is a graphical interface for easily creating SSH tunnels. SSH tunnels (a.k.a. "port forwarding") allow users to redirect traffic from one port on one computer to another computer and port. The main advantages of this solution are:<br />
- No need to open new connection ports inside firewalls<br />
- No need to set up a proxy or a gateway when remote computers are not accessible directly<br />
- Redirected traffic is secured by SSH encryption<br />

<SousSousParagraphe>What is the best way to secure my MobaXterm installation?
<br />
MobaXterm is already a secure program: its SSH connections are encrypted using well-known algorithms, its passwords can be stored with strong encryption. However, depending on your company security rules, you can disable some features which may be considered as unsafe: in the "customizer" program, go to the "Settings" tab, then to the "Security" tab. Each setting can be kept unchecked (less secure) or checked (more secure), you will have to make some choices between features and security.<br />
For instance:<br />
- if users do not use any of the embedded servers, we recommend checking the "Disable embedded servers" box.<br />
- if users do not need any packet capture or network scanner / port scanner tools, we recommend checking the corresponding items<br />
- we would also recommend disabling insecure protocols, such as telnet or rlogin and use SSH instead. In case an insecure protocol is needed and cannot be replaced by SSH, then it could be "tunneled" through a secure SSH connection (you can use the "SSH gateway" setting in telnet sessions to do so).<br />

<SousSousParagraphe>My SSH connection freezes or drops out after N seconds of inactivity.

<SousSousParagraphe>When connecting to an SSH server, I get the following error message: "WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!"

If you changed or re-install this server recently, and if you are really sure that no other computer is using its IP address, then you can reset this alarm by deleting MobaXterm ~/.ssh/known_hosts file: open a new MobaXterm terminal tab and type the following command:<br />
