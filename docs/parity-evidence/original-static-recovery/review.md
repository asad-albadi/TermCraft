# Independent static evidence review

Verdict: **accepted as qualified RECOVERED evidence for future implementation targets**, not runtime-exposed catalog, engine parity, native qualification, or a completion-count increment. Reviewed 2026-11-25 without launching the original, any extracted game, or a GUI. No product code changed.

## Checks actually performed

- Recomputed all 14 retained manifest SHA-256s and sizes: no mismatch. Recomputed the three original-input and eight SDK/wrapper source/binary hashes recorded in sources.json: no mismatch.
- Cross-checked all 64 parsed TPF0 starts against PE resource start records, their object end bounds against resource lengths, and the count of TPF0-starting resources: all 64 correspond, with no out-of-resource parse end. Independently verified all 135 catalog property-name offsets and 134 scalar property values against original bytes (the remaining value is a binary blob). This supports the actual serialized menu, toolbar and timer records rather than a loose string-search catalog.
- Verified published-method names and preceding target addresses directly in original bytes; checked ST handler literals at the recorded raw/VA conversions and inspected retained disassembly. Sender-string concatenation and the six matching selectors are strong recovered dispatch evidence. Sender-field meaning and the unnamed imported call remain qualified by the report; process creation/success was not observed.
- Independently redecoded all seven linked 32-bit companion game members using bounded Python LZMA, matched retained decoded bytes/hashes and MZ signatures, and checked all 114 cited help strings at their exact decoded raw offsets. Inspected Nimesweeper disassembly immediates supporting the seven substituted key characters.
- Rehashed MOBASE/XW source slices and decoded outputs. Replayed the recorded SDK decoder under 768MiB address-space, 30 CPU-second and 256MiB output limits with a 40-second wall bound: exit 0, result 0, status 4, all 2,555,929 post-header input bytes consumed, exact 15,222,391-byte output and identical SHA-256. The replay finished; its temporary output was removed.
- Independently walked all 56 stored MOBASE ZIP entries and recomputed CRC32: exactly 21 mismatches, including stgames.exe. Confirmed that member SHA-256 and both identity/version string offsets exactly match the report.

## Meaning and limits

The disabled Terminal games item is a sibling heading. Typespeed is explicitly serialized Visible=false. The other thirteen game items have no serialized Visible field; calling these thirteen runtime-visible or enabled would exceed the evidence. Tux consolesaver is separately declared and is not a fourteenth game engine. Games1 also has an OnClick handler, so initialization/menu-time mutation is specifically still possible. Serialized timer intervals and disabled states establish neither inactivity defaults nor effective frame timing.

SDK confidence is reproducible decoding of these exact supplied bytes, using hash-recorded official-source files with public-domain notices in the retained SDK headers/source. It is **not** proof of the original application's complete ResourceDecoder pipeline or final runtime materialization. The independently reproduced CRC anomalies prevent treating the member as checksum-clean. Their cause must remain unknown; neither corruption nor an intentional additional transform is established. The upstream version string is a correspondence lead, not permission to substitute modern puzzle rules or assert identical historical behavior. Existing 7zz byte equality supports helper provenance; it was not the successful MOBASE decoder, and no independent vendor detached signature was claimed for its HTTPS archive.

No blocking inconsistency was found in the central qualified records. Two small documentation/schema cautions remain: catalog.json's unresolved item still says the puzzle payload is unresolved although a later stgames section now recovers qualified bytes; interpret only puzzle rules/controls and final runtime materialization as unresolved. resource-decoding.json retains decoded_bytes=0/exit_code=2 for the failed 7zz attempt alongside final_decoded_* fields; consumers must read the final_method fields and not mistake the failed preliminary attempt for the final decoder outcome.

This evidence is sufficient to replace speculative game-name scope with a resource-declared target list: seven terminal games plus six ST selectors, with Typespeed explicitly hidden in the resource and Tux treated separately. It supports the help-declared rules/controls where quoted. It does not complete missing Ctris/nInvaders controls, Soliterm move semantics/defaults, Termwalk key bindings, six puzzle engines, screensaver behavior, or original runtime parity. Preserve RECOVERED/MEASURED/ESTIMATED distinctions per field and do not infer any global cap or default from one handler.
