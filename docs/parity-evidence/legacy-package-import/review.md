## Source review and limits

The ZIP reader bounds the source snapshot, entry count, central-directory bytes, ZIP output per file and aggregate, and decoded output per file and aggregate. It independently preflights raw central names before ZIP-reader deduplication. Full header consistency and overlap validation run before extraction, and reads continue through EOF for CRC checks. Filenames are ASCII-only with traversal, absolute/drive paths, backslashes, ADS, devices, trailing dots/spaces, duplicate/case conflicts and file/directory conflicts rejected. Encrypted entries, links and special files fail. No metadata from the input is applied as host permissions.

Nested LZMA is detected conservatively from bytes; it has no universal magic. Recognized streams are constrained by dictionary, context and output limits, and decoder failure/truncation/trailing data cannot fall back to raw import. Conservative rejection of some ambiguous ordinary binaries is a documented compatibility limit. Ordinary PE/document/gzip members in the Sqlite fixture remain ordinary bytes; the gzip manpage is identified, not recursively unpacked. PE labels identify header machine fields only and do not prove loadability or dependencies.

The source is opened as a regular nonblocking file without following the final symlink, copied and hashed into a private snapshot, and never reopened for import. Reviewed payloads are private implementation state and are rehashed while copied. Capability-relative staging, root nofollow, a regular nonblocking exclusive lock, cancellation before commit, and final rename preserve publication behavior. Failed stages are removed; preexisting final imports are rejected; the operation does not alter runnable package registries. This assumes the app-owned directory and current-account authority model already used by the application. It is not a hostile-current-account or OS execution sandbox. Root creation uses private Unix permissions, and imported files receive no executable bits on Unix.

Generated local metadata uses `termcraft.local-legacy-import.v1` and explicitly records unauthenticated provenance, source/payload hashes and disabled execution. There is no invented vendor version/schema or inferred architecture from container filename. The patch's changes to existing P05 code are limited to exporting the new separate module, and UI state/render wiring; P05/P06 pinned command catalogs, grants, leases, sealed images, retirement and launch behavior are unchanged. Original runtime/dependency resolution and command discovery remain unimplemented.

The UI permits only one worker at a time and hides preview actions while it runs, so no separate generation protocol is needed for these replies. Worker disposal cancels and joins; inspection/import run off paint. The panel shows the source fingerprint and inventory, requires explicit import, and offers discard/cancel. It adds no file-open, folder-open, shell, PATH modification, plugin registration, or executable-launch action. Runtime/publisher/dependency qualifications are visible; status reports only paths and errors, without a payload-output or credential collection route.

## Dependency security rationale

On the review date, the upstream package listing identified zip 9.8.2; the exact current pin and narrow flate2-only feature selection are justified. The [maintainers' security policy](https://github.com/zip-rs/zip2/blob/v9.8.2/SECURITY.md) explains latest-release support and opt-in header consistency in 9.x. [RUSTSEC-2026-0548](https://rustsec.org/advisories/RUSTSEC-2026-0548.html) requires the consistency opt-in; this implementation calls `validate_header_consistency()` and has a regression for mismatched local/central names. [RUSTSEC-2026-0547](https://rustsec.org/advisories/RUSTSEC-2026-0547.html) concerns legacy ZIP decoders, which are disabled here and fixed before the pinned version. [RUSTSEC-2026-0545](https://rustsec.org/advisories/RUSTSEC-2026-0545.html) concerns AES decryption, which is disabled and not invoked. This code manually writes validated regular members rather than using ZIP extraction/permission APIs implicated by the symlink extraction advisories. These observations are a bounded advisory/applicability review, not a blanket dependency security certification or full-tree cargo-audit result. The separate [lzma-rs 0.3.0 codec](https://docs.rs/crate/lzma-rs/latest) is pinned with application-enforced budgets; Python's smaller supported context range must not replace the real companion requirements.

Integration should retain the documented missing-runtime/disabled-command wording and run MAIN's focused checks after applying the patch. Retain implementation count 42/60 (70%) and strict native/original count 0 unless the parent independently qualifies a different checkpoint.
