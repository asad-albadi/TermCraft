## Important finding

**[P2] Terminate and reap the launcher when startup times out.** In `runner/run_mosh_roaming.py:57–60`, `launcher.wait(timeout=8)` can raise before `owner` is assigned. The cleanup at lines 113–134 terminates only `client` and the parsed server `owner`; it never terminates the still-running launcher. Its general `waitpid(-1, WNOHANG)` loop waits three seconds and then raises, leaving that owned process running. Consequently the runner's all-owned-jobs cleanup guarantee does not hold on this supported failure path. The outer helper's `subprocess.run(..., timeout=180)` likewise does not establish descendant cleanup if the whole fixture times out.

A focused fault-injection check compiled the exact `run_case` function from the reviewed runner, replaced network operations with inert fakes, and replaced executable launch with a single owned Python sleeper whose wait timed out. After the cleanup loop, the function raised `owned descendants not fully reaped` and the owned launcher was independently confirmed still alive. The review then killed and reaped that probe process. This check did not launch Mosh, change host networking, open hardware, or repeat the matrix. No production or runner fix was made. Retain the observed successful-run evidence, but resolve and negatively test startup/outer-timeout cleanup before treating the runner as fully bounded on failure.
