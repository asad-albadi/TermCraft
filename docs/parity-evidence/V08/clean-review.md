## Important findings

1. **P2 — Analyzer accepts incomplete runtime results and failed omitted scenarios.** `clean-analyze.py:26–27` checks only ten of thirteen suite records, omitting minimal browser and both inventory scenarios. Lines 32 and 35 copy Iperf/Unix result arrays and browser version text without validating required members, versions, exit codes, byte counts, or expected version. Its final step reindexes evidence rather than checking an earlier evidence index. A disposable copy of the analyzer/evidence accepted `clean-iperf-results.json=[]`, `clean-unix-results.json=[]`, browser version `BROKEN VERSION PROBE`, and minimal-browser record exit 99 together, returning zero and emitting them into a new observations file. The copy used read-only access to original archive/extraction paths; it was deleted afterward. Validate the entire expected scenario set and schemas/semantic outputs, including empty/missing/partial results, before treating this tool as a qualification gate. Current retained direct-run results are nonempty and their client logs show the actual transfers; this finding does not invalidate that historical run.

2. **P2 — Negative/UI/browser replay completion does not assert the observed behavior.** `clean-scenarios/absent.sh` and `absent-bundled.sh` assert only that installed Mosh is absent, then request a session and capture a screenshot. They do not check the required provider-specific error or absence of fallback. `browser-runtime.sh:7–24` leaves `set +e` enabled, prints but does not assert the version return code, and returns normally for sandbox failure, success, or timeout. The analyzer then assigns fixed negative/browser statements. A future error-text change, missing Perl precondition, version failure or changed sandbox outcome can therefore remain green. Preserve these as manually inspected observations until replay has structured assertions for the expected outcome and records timeout/partial distinctly. I visually checked the retained bundled-Mosh screenshot: it explicitly says system Perl at `/usr/bin/perl` is required. The actual browser log records version exit 0 and sandbox exit -6 with the setuid-helper fatal diagnostic; the namespace probe records denied user namespace creation. These are valid bounded observations, not proof that every supported native sandbox fails.

3. **P2 — Iperf replay checks generic throughput output, not the stated exact transfer.** `clean-scenarios/iperf.sh:15–17` accepts any successful client output containing `bits/sec`, then writes the requested constant 262144 into its result. It does not independently assert the completed byte count or server receipt. The retained Iperf 2 client shows 256 KBytes; Iperf 3 shows 256 KBytes on sender and receiver, so the current direct-payload observation is supported by manual log review. Future exact-byte qualification needs numeric transfer/receiver validation, preferably machine-readable Iperf 3 output and a specific Iperf 2 parser, rather than the requested argument alone.
