## Results

- `probe.sh`: genuine packaged Chromium 158.0.8127.88 headless `file:///tmp/offline.html` run exits 0 and returns the exact `V08_SANDBOX_OFFLINE_OK` DOM marker. A subsequent live headless instance supplies actual `/proc` sandbox records in `browser-processes.json`.
- `gui3.sh`: actual TermCraft under an owned private Xvfb opens the configured BundledChromium embedded Browser session. `gui3-browser-before.png` displays the local page marker. `gui3-browser-input.png` displays `V08_NATIVE_INPUT_OK` in the page input and `Native typed: V08_NATIVE_INPUT_OK` from page JavaScript; `gui3-http.log` records the corresponding final loopback request. Requests intentionally hit the minimal fixture server's nonexistent receipt path and receive HTTP 404; their logged query proves input delivery, not a successful receipt API.
- The same actual native application, after explicitly moving focus out of the embedded browser, accepts its new-terminal shortcut and focused terminal-widget typing. The shell writes exact `V08_NAMESPACE_NATIVE_PTY_OK\n` bytes to `gui3-pty-marker.txt`; `gui3-pty.png` captures the terminal. Final native run exits 0.
- `gui3-browser-processes.json` captures the actual native browser's executable paths, SHA-256, arguments, full status, UID/GID maps and namespace identities. The application extracts its browser into private `/tmp/termcraft-browser-runtime-*`; all 12 captured Chromium executable hashes equal packaged `35d59a09075378c3c7ec9b60ebd46bb327563b87f6feb1365417fea4349db126`. Five renderer processes have `Seccomp: 2`, `NoNewPrivs: 1`, UID 1000, and nested user/PID namespaces distinct from the browser parent. This checks the browser's own nested sandbox, beyond the outer bwrap namespace. Browser parent, crash handler and some service/GPU processes do not all report renderer seccomp; no broader claim is made.
- All **1415** package manifest entries match, source snapshot identity matches retained release-integrity, and archive SHA-256 matches. Runtime package inventory exactly matches the prior declared-runtime image inventory. No system Chromium is installed. `verified-inputs.json` records actual native sandbox assertions and identity checks.

Only empty `/opt/termcraft` and `/evidence` mountpoint directories were added afterward. Export contents and their extraction are validation scratch, not host runtime installation.

`run.py` records exact actual bwrap command for each run. No network route to external services is provided. No privileged Docker, Docker seccomp override, root browser, `--no-sandbox` or `--disable-setuid-sandbox` is used. Chromium's internally generated unsandboxed zygote/service flags are preserved as actual process observations; renderer namespace/seccomp status is verified directly.

## Replay and limits

Existing exported rootfs and immutable package allow `python docs/parity-evidence/V08/clean-namespace/run.py probe` or `... run.py gui3`. These write new observations to their scenario filenames; preserve this sealed evidence before any replay, or copy the harness to a separate evidence folder and adjust paths. `export-root.py` intentionally refuses to extract over an existing root. `verify-inputs.py` checks the final captured browser executable hashes/nested renderer protection and package/archive integrity, independently of scenario success codes.

The previous Docker sandbox-blocked evidence remains valid and untouched. This establishes an alternative isolated native Linux userspace success path; it does not make that Docker configuration support Chromium namespaces. It does not qualify the current advanced source, a newly rebuilt release, physical hardware/GPU, native distro install/upgrade matrices, credential-vault upgrade contents, external network browser behavior, Windows/macOS, original parity or signing/notarization. Full V08 and release qualification remain open. Root-level matrix updates and independent review are separate.
