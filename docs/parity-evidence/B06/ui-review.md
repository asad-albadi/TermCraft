## Important: Untangle loses a drag when press and motion arrive in one frame (P2)

`src/ui/games/play.rs:1126–1139` uses `response.interact_pointer_pos()` to identify which vertex began a drag. That is the current pointer position after all input events in the frame, rather than the button-press origin. When the backend batches a press on a vertex and more than 20 points of motion before repaint, the vertex is no longer within the acquisition radius. `play.dragging` stays empty; subsequent motion/release makes no core move. The same lookup can also select a different vertex at the moved position; that consequence is source inference, not a separately executed reproduction. This affects ordinary mouse-event batching, without requiring native IME, malformed input or an original-runtime oracle.

Independent real-egui reproduction uses seed1, two initial layout frames and the displayed position of vertex0, followed by a hover, a primary press at that vertex and `PointerMoved(origin + vec2(65.,20.))` in the same `RawInput`, then a later release at the destination. Both positions are inside the board. The final scene remains byte-for-byte equal to the initial scene and the intended scene-change assertion fails. The control case with exactly the same press, motion and release split across separate frames passes, including a single Undo restoring the original scene. This is an actual production `games_frame`/`draw_scene` path in pinned egui0.36.2, not a replacement renderer. The owner's Untangle test covers keyboard movement only and therefore does not detect this defect.

Acquire the source vertex from the pressed pointer position/press origin, retaining current-position motion preview, and add the batched press/motion regression alongside ordinary drag/undo. Evidence: `target/agent-work/b06-ui-review/drag-probe-inside.log` (one pass, one intended failure). The earlier `drag-probe.log` used an outside-board destination and is superseded by the within-board reproduction. Review source/probes are isolated at `target/agent-work/b06-ui-review/source`; only the independent test module and private Cargo identity differ from the frozen candidate. No implementation fix was made by this reviewer.
