# B06 independent puzzle engines

Evidence class: **RECOVERED historical source correspondence**, not measured original behavior. These are six playable independent Rust implementations, with native-scene data and no external process, original asset, unsafe code, dependency, or ambient I/O. This component alone does not complete B06 or establish native parity.

All seeds are local `u64` SplitMix64 seeds. **They do not identify original or upstream game IDs**. Puzzle layouts, PRNG sequence, difficulty distributions, animation, pixel rendering, preset menus, save format, keyboard focus and complete upstream customization are not asserted equivalent. Recursive generation searches have hard node budgets (Net 20,000; Solo/Map 10,000 per search); budget exhaustion rejects a candidate/removal rather than asserting uniqueness. Board dimensions and candidate limits are fixed, and graph/region/flood iterations monotonically consume finite cells/vertices. The UI should create once per new game, never per paint; future arbitrary-size customization would need a cancellable worker. Undo is bounded to the latest 256 state-changing inputs. No-op and invalid inputs add no history. Reset restarts the exact local seed and clears history/deaths. Solved/failed boards accept undo or reset; other puzzle inputs return an error (Net highlight movement remains available as UI state). The UI owns selection/cursor and converts native controls into the typed inputs; no GUI toolkit is required by these cores. Net highlight source is separately held UI state, wraps on Ctrl+arrows, adds no puzzle undo, and persists through puzzle undo; reset recentres it. `HalfTurn` and `Jumble { seed }` are single atomic puzzle inputs. Explicit jumble seeds make replay deterministic without claiming upstream UI PRNG identity; locked tiles are skipped and a visually unchanged jumble adds no undo.

## UI contract

`PuzzleSession::new(PuzzleKind, seed)`, `new_map(seed, MapPreset)`, `input` (alias `apply`), `undo`, `reset`, `scene`, `outcome`, `kind`, `seed`, and `can_undo` are the public entry points. `input` returns `Result<bool, &'static str>`: `true` changes state, `false` is a safe no-op, error leaves the entire state/history unchanged. `PuzzleKind::ALL`, `selector`, and `help` support registry presentation. Outcome is `Playing`, `Won`, or `Lost` (only Mines and Guess lose).

`PuzzleScene` variants carry typed bounded data. Net masks are north=1/east=2/south=4/west=8 and include connected/locked markers. Mines hides every unexposed mine. Solo digits are 0 blank/1–9 and pencil bits use `1 << digit`. Guess colours are 0 empty/1–6. Map region colours are 0 blank/1–4; its cell vector maps grid squares to region indices. All dimensions and region counts in rendering/input come from the scene. Pencil input rejects every filled region, including pencil-clear, transactionally. `MapScene.generation` discloses randomized/fallback generation and `certificate` records a complete logical replay (counts, not an original runtime trace). Untangle positions are integer normalized coordinates in inclusive 0..=1000; out-of-range and invalid vertex inputs are rejected. No scene contains a hidden answer while the puzzle is playing.

## Verification scope

The private dependency-free component suite contains 29 tests: source-derived transitions for all six games; multiple-seed win playthroughs for all engines; loss paths in Mines/Guess; first-click safety and deductibility; Net uniqueness; Sudoku and Map unique solutions and Normal-necessary deduction certificates for both presets and forced fallback; region connectivity; reset/replay; bounded undo; fatal-move recovery; transactional range/given errors; duplicate feedback; crossing/endpoint/overlap cases. Linux tests pass. `cargo check` passes for Windows x86_64 MSVC and macOS aarch64; this verifies Rust compilation only, not native GUI execution, linking, packaging or original behavior. Clippy with warnings denied passes. Round-0 controlled mutations to one source-derived rule per game each produce a behavioral failing fixture, and all originals are restored before the green suite; the erase fixture was strengthened to assert literal zero after its first mutation check exposed insufficient coverage. Parent application/registry/UI integration and full product gates remain with their owners.
