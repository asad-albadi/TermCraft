The exact historical `net.c:1746–1825` auxiliary-answer Solve path decodes every solution tile and sets `LOCKED` on it (line 1775), then constructs unlock/rotate/relock transitions to reach that state. The candidate likewise has its complete generated answer, so this is the corresponding source path, rather than the upstream no-aux partial-solver case.

Public API reproduction: construct default Net seed 9, lock cell 0, invoke `PuzzleSession::solve()`, inspect `NetScene`. Candidate reports Won and only **1/25 locked**. The recovered auxiliary Solve results in **25/25 locked**. The current generic Solve test checks outcome, scene restoration and assistance, so it misses this visible state mismatch. Set the solved-state locks consistently with the source, retain the atomic undo snapshot (which should restore the original partial locks), and add a behavioral regression covering locks through Solve/undo/redo. This is a focused newly implemented Solve correction; it does not request the fifteen disabled advanced variants.
