## Important findings

1. **[P2] Map permits pencil marks on a coloured editable region.** In `map.rs:209-215`, the pencil branch only checks givens/range and writes stipples even when `self.colours[region] != 0`. Historical `map.c:2521-2524` explicitly rejects pencil operations on any filled region. Reproduced through the public session API with seed 0: choose the first non-given region, Colour(region,1), then MapPencil(region,2). The latter returns success and changes state, instead of rejecting transactionally. `puzzle-review-probe.rs` and `puzzle-review-probe.log` retain the independent behavioral failure (exit 101). Reject this operation for filled regions and add a source-derived fixture asserting unchanged scene/history. The existing Map mutation only tests border conflicts and does not cover this rule.

2. **[P2, completeness gate] Map substitutes a smaller default puzzle.** `map.rs` fixes 64 cells and 16 regions throughout generation, scenes and transitions. Historical `map.c:99-114` defaults to 20×15/30 regions, or 16×18/30 under `PORTRAIT_SCREEN`. The compact engine is substantive and normally generated, rather than a hardcoded toy, but it is not the recovered default game. Its fallback is a fixed 4×4 region grid with only one missing forced colour; fallback use is not exposed or directly tested. Preserve the explicit compact-preset qualification and keep default equivalence pending unless the actual recovered defaults and normal-difficulty generation contract are implemented. Independent randomness, polyomino aesthetics and palette differences alone are acceptable; replacing board size, region count and advertised difficulty is a separate scope change.

## Positive rule and safety assessment

Net generates spanning trees and verifies reciprocal port domains plus connected completion; fixed total degree 48 on 25 tiles makes full connectivity sufficient for a tree. The uniqueness fallback is the seed-0 candidate included in uniqueness sampling. Mines defers placement until first reveal, excludes its eight neighbours, accepts layouts with explicit local/subset/global-count deductions, protects flags, floods zeroes, chords matching flags, loses on mine reveal and preserves deaths across undo. Consulting candidate truth for consistency checks in its logical solver does not make deductions guesses. The solver is conservative; inability to prove a layout rejects it. The corner-block fallback is safe by construction but is not explicitly forced by current tests.

Solo and Map retain a known valid solution and remove clues only when solution count is one. Search exhaustion returns the requested solution-count limit, so an incomplete uniqueness search is conservatively rejected, not asserted unique. Both counters assume valid partial givens internally; this is satisfied by their generators, and they are not public arbitrary-board solvers. Their current uniqueness tests reuse production counters, so they are useful regressions rather than independent solver oracles. Net has the same test-oracle limitation. Multi-seed tests also exercise completion against stored solutions; not every game uses only public session inputs for those playthroughs.

Guess's multiset feedback counts duplicates correctly and held pegs transfer after submission. Mines/Guess loss and recovery, fixed starting clues, invalid bounds, undo limit and reset paths are covered. Untangle uses bounded integer coordinates and i64 orientation products, counts nonincident endpoint contact/overlap, and skips graph-shared endpoints exactly as historical completion does. Its outerplanar triangulation generator is a restricted, disclosed source of valid planar puzzles, not reproduction of upstream graph distribution.

Public inputs cannot inject arbitrary dimensions, masks, indices or floating-point coordinates. Out-of-range errors roll state back; unchanged operations add no history. History is capped at 256 states. Scenes reveal no stored solution while Playing; scene vectors and graph references come from bounded private generators. Net/Solo/Map searches have explicit 20k/10k/10k node budgets; generation candidate/removal loops and Mines deductions/floods are finite. Current sample suite completed in 0.15s after compilation on this host. This is not a worst-case UI frame-time guarantee; generation belongs on new-game creation, not paint. No cancellation/worker or arbitrary-size API exists here.
