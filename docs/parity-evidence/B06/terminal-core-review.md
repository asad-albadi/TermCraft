## Important integration contract finding

**P2 — nInvaders does not expose or document its player row.** Owned `invaders.rs:8–18,57–68` exports a 32×24 scene and `player_x` only, while `hits()` at lines 82/89 places player collision/ground-contact at row 22 and fire starts at row 21. `API.md` does not tell a renderer to use row 22. A reasonable height-minus-one renderer therefore draws at row 23 and shows damage before visible contact. A public-session probe (seed 0, Start, Tick repeatedly) reproduces first damage on tick 85, from a projectile previously at `(15,21)`, when lives change 3→2; the collision is on row 22. Expose an explicit player_y (preferred), or document the fixed row and ensure a shared consumer constant/test. The private, still-in-progress UI currently draws `s.height-1`; root has routed that integration followup to its owner. That UI is not an acceptance candidate in this review; the owned finding is ambiguity in the frozen scene contract.

## Smaller owned followups

- **P3 — public Piece helper has an unstated coordinate precondition.** `blocks.rs:28–29` adds offsets to freely constructible public i32 coordinates. `Piece { kind:1, rotation:0, x:i32::MAX, y:0 }.cells()` panics in a debug build (and wraps with overflow checks off). Normal session scenes are bounded and cannot reach this through TerminalInput, so this is not a game-input crash. Either make the helper total with checked/saturating arithmetic or document that it accepts session-produced, bounded positions only; broad public-API adversarial-safety claims must exclude arbitrary constructed Piece values until then.
- **P3 — paused-input documentation overstates rejection.** `PROVENANCE.md:19` says invalid/unsupported inputs return an error. Paused Ctris, Mines, and started nInvaders instead return `Ok(false)` for `Digit {cell:usize::MAX,value:255}` because pause short-circuits validation. State/history remain unchanged. Document ignored paused inputs, or validate before the pause shortcut if uniform Err is intended.
- **P3 — solver-independence wording in owner evidence.** `terminal-core.md` says its 64-seed uniqueness count used an independent solver. `grids.rs`'s generation test calls the same production `count_solutions` routine used for clue removal, with a larger budget. The owner test proves consistency, not independent implementation. This review adds genuine independent certification for seeds 64–127 using a separately written bitmask MRV solver; all 64 had exactly one solution. Correct the owner wording rather than treating the original test as an independent oracle.
