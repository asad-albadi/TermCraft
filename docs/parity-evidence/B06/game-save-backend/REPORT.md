# B06 pure game Save/Load backend

Implemented privately against `b06-advanced-ui/work`, preserving all accepted pure cores. Production payload has exactly three paths: new `src/games/persistence.rs`, narrow common `src/games/library.rs` session hooks/constructor metadata, and `src/games/mod.rs` export. MAIN was not edited. Private package version is0.1.914; normal binary is `termcraft-game-save914`. `candidate-maps.json` contains exact baseline/candidate SHA256; `core-dependency-hashes.json` proves all16accepted pure-core Rust files byte-identical. `backend.patch` and `payload/` are review/integration artifacts.

The own-format JSON envelope requires format/version/exact engine identity/seed/initial constructor/typed successful journal/full private state-and-history digest. Separate manual serde DTO adapters preserve all13games and every native configuration without adding serialization to rule cores. Configured and default constructor paths remain distinct. Solitaire variant/original passes, terminal mine presets, Termwalk size, Map orientation, all PuzzleConfig and SoloVariant settings are retained. `initial_settings()` exposes native-typed read-only constructor choices for loaded UI menu drafts.

`save_bytes()` and `load_bytes()` are pure byte APIs; no filesystem or UI behavior is included. Load constructs and verifies a separate candidate. All errors leave the caller's existing game and input bytes untouched. Successful input/undo/redo/Solve hooks preserve native return values and record only `Ok(true)`/true; native cores already compare complete internal state, including RNG, for success. Reset resets the native initial board and starts a fresh journal. Assistance, hidden solutions, initial state, undo/future stacks, death counters and Net source are covered by streamed SHA256 over the complete private Core Debug representation. SHA256 is integrity checking, not authentication.

`engine_identity()` computes a cached SHA256 of compiled `include_bytes!` contents for all19game sources:16pure-core files plus common library/mod/persistence. This automatically invalidates files after changes to constructor/replay/DTO/core semantics, before generating the candidate. No source hash constants need maintenance and hashing self-source has no cycle.

## Resource bounds

Input maximum262144bytes; nesting16;4096journal entries;32768expanded successful actions. Native config validators constrain all dimensions, topology combinations and generator search budgets. Action operands have explicit board/value/coordinate/card-count bounds. Unknown fields/opcodes, unsuccessful operations, malformed data, versions and engine mismatches fail. Reset is not an import opcode, so imported journals cannot repeatedly regenerate starting puzzles. One native bounded initial generator runs per candidate. Successful Mines first reveals are symbolically tracked through the256-slot Undo/Redo stacks; every transition from unplaced to placed is charged6million deduction steps (native2Mprimary+eight500kfallback bounds). Replay charges1024work units per expanded step plus16million initial-generation allowance, limited64million. This gives at most7first-reveal generations in one imported file and prevents an Undo/regenerate journal from multiplying native generation work arbitrarily. Solve cannot rerun generation and is bounded by action/expanded-work limits.

Successful consecutive timer ticks use typed `Ticks(u16)` runs, verified one successful native tick at a time on import. The UI timers are500ms Ctris and100ms Ninvaders.32768steps correspond to4h33m of Ctris ticks or54m36s Ninvaders ticks before counting player actions.4096separate entries permit substantial input between tick runs. No-op/paused/finished ticks never grow the journal. The journal limit never changes gameplay; it only makes Save return a readable quota error, and Reset restores a fresh saveable journal.

Measured10000timer attempts: Ctris111successful ticks before loss produced283bytes; Ninvaders109successful ticks before loss produced318bytes.10000paused Ctris ticks produced byte-identical saves. Expanded-step/work limits are checked before candidate construction and reject compressed oversized tick runs.
