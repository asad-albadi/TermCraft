The initial native package attempt failed with rustc SIGSEGV. A 32 MiB compiler stack retry of the same source and profile finished the optimized app compilation in 2m44s but the staging checksum then failed for `openssl-source.tar.gz`. The original failure is retained. Recorded full-buffer rereads match all 12 times, and this review independently matched the cached and packaged bytes to the same pin. The exact-cache retry used the genuine Cargo release outputs, with the app build reporting 0.26s for its cached check and the outer stage succeeding in 44.92s. The reason for the isolated read/hash failure was not established. This is evidence of a successful strict retry, not of a waived hash, source change, changed pin, or reproducible root cause.

## Accepted runtime claims

- **Clean declared-runtime Linux X11 startup and bounded RDP smoke.** Recorded command uses the previously audited Arch runtime export for image `sha256:1ab61a2bb16febd0a86829a43c26849b06ca82aca31be8385880cc7a3570c79d`. It read-only mounts the rootfs, exact extracted archive and probe tools. It uses a cleared environment, private namespaces, its own Xvfb with private cookie and display TCP disabled, and fresh home/temp. It mounts no host display, host home, or host library tree and has no external network access. The package actually returned app help, RDP helper Ready v1, and a nonblank 1280×800 screenshot. I visually reviewed the light System-theme workspace with the emerald penguin. Recorded app-started loopback RDP reached initial TPKT and checked the live helper executable against the package hash and required memfd seals, plus workspace preservation and fixture cleanup. This is not a complete authenticated RDP desktop. The older rootfs audit establishes userspace provenance, not reuse of a previous app artifact for these claims.
- **Configured-host Linux Direct XDMCP.** The separately sealed fixture used the same package, saved Direct localhost:1177 session, bidirectional clipboard on a private parent, actual xdm and actual packaged app. Independent client/pixel evidence established a negotiated, cookie-authenticated green 800×600 desktop, rejection of a wrong cookie and exact 39/47-byte UTF-8 clipboard transfer in opposite directions. The package, frozen feature pin and live app-owned engine observations agree. The visible cancel button under private Xvfb removed the owned nested process and socket while leaving the app, xdm and parent running. The app then exited 0 via WM_DELETE and the parent remained responsive. Cage with packaged Xwayland provided separate authenticated desktop and clipboard positives, but no XTEST cancel pass. The app's stale waiting label was not used as a success signal. This was not a clean-image XDMCP run or desktop host clipboard test.

Not qualified by this evidence are the subsequent private keyboard-layout and chooser work, actual Indirect XDMCP or PAM, external endpoints, full RDP interoperability, native Windows/macOS, physical GPU and serial or smart-card hardware, original-product comparisons, and signing/notarization. Bundled artifacts and test mocks alone do not qualify all optional runtimes in this archive.
