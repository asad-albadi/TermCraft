# Optional Wayland desktop-sharing helper

The application has no direct PipeWire library dependency. Linux Wayland VNC sharing needs the optional package-adjacent `termcraft-wayland-engine`, a matching SHA-256 entry and `wayland_helper_version` in `PACKAGE-MANIFEST.json`, and a user-approved XDG ScreenCast/RemoteDesktop session. It never searches PATH or installs a host service. Missing or mismatched helpers fail only this source. Legacy packages without the optional manifest field keep working.

Build separately with `CARGO_BUILD_JOBS=2 cargo build --locked --release --manifest-path engines/wayland/Cargo.toml`, then pass its exact executable to `scripts/package-release.py --wayland-helper-binary PATH` along with ordinary release inputs. The packager keeps helper selection optional, reports its explicit prebuilt provenance, copies its source and lockfile, includes Rust dependency notices, hashes the executable, and inventories native libraries. The main app and RDP binaries are distinct inputs and remain separate.

Bindings: pipewire, pipewire-sys, libspa, libspa-sys **0.10.1**, MIT, from https://gitlab.freedesktop.org/pipewire/pipewire-rs and crates.io. Their exact registry checksums and transitive dependencies are in `engines/wayland/Cargo.lock`; dependency notices are generated from locked Cargo metadata by the release packager. Native **libpipewire-0.3.so.0 >= 0.3.65**, matching SPA modules and a working portal backend are required only for this helper. The private fixture uses system PipeWire **1.6.11**; it does not establish a broader distribution ABI qualification. PipeWire is distributed under the MIT license with component notices; upstream source and license: https://gitlab.freedesktop.org/pipewire/pipewire. Native system libraries and SPA plugins are inventoried, not bundled or installed by this option.

The helper receives only the portal's connected remote descriptor and a private bounded framebuffer channel. The application executes an immutable sealed image of the verified binary, keeps consent/control in the source worker, bounds mapped frames and IPC to 8,388,608 RGBA pixels, coalesces frames, and kills/reaps only its owned helper on Stop. No screen file or clipboard history is written. The helper is a process-isolation/optional-dependency boundary, not a claim of kernel sandboxing.

Current format limits: one portal-selected stream; packed RGB/BGR/RGBx/BGRx/RGBA/BGRA memory-backed frames, positive stride, up to 4096 x 2048 negotiated dimensions within the pixel limit. DMA-BUF-only, planar/YUV, rotation/crop metadata, multi-stream and changing framebuffer dimensions are not supported. The portal's logical coordinates are used for control. D-Bus Notify methods are used without opening an EIS connection. Clipboard sharing remains explicitly unavailable for this source.

The private synthetic-video + mock-portal test proves real PipeWire transport and request/session/input API behavior without touching a host screen, clipboard, input device or permission dialog. It is not native compositor, actual consent-dialog, host portal or original-application parity qualification.
